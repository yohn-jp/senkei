# Official Match authority boundary

This package is a provider-independent **server-side contract and orchestration boundary**. It does not configure or implement an official service, login, asset store, queue, Enbu worker, settlement database, rating formula, ticket policy, or replay permission policy. In particular, a completed local simulation and a digest or locally cached receipt do not establish an official result. `ONLINE.md` still describes official PvP as unimplemented.

An integrator must supply trusted implementations for every port. Their responsibilities are part of the security boundary:

- Authentication resolves credentials to an authenticated player; admission atomically checks ownership of the submitted attacker revision, resolves a registered immutable defense, enforces the chosen ticket and anti-abuse policy, and binds an idempotency key to one request and Match.
- The asynchronous worker receives the retained complete snapshots, initial state, programs, package and authored World. `OfficialCorePort` must use the real core to recompute and verify the complete input digest, all relevant content and versions, execute Enbu, check the result digest and produce/verify its allowlisted public projection. Identity comparisons in this package do not replace those checks.
- Settlement atomically persists the retained input, result, replay, ticket accounting and rating change. Its durable idempotency, serialization, conflict detection, provenance, recovery and inquiry must be implemented and verified by the provider. This package cannot establish those guarantees from a TypeScript interface. `pending` and `outcome_unknown` are not commits. The Match receipt grants no progression reward or entitlement.
- Replay access is a separate policy from publishing or forking tactics. Only a committed record with matching Match/input/result/RulePackage/paired World identities may be read. The core must verify the exact public projection's semantic event/field allowlist and visibility; structural checks alone cannot establish secrecy. Public result projection excludes CU and all private inputs and diagnostics.

`executeAdmittedMatch` and `inquireMatch` are authority-job operations; they are not public endpoints. Network adapters must authenticate and authorize any user-facing inquiry. `admitMatch` returns only a Match reference. `readPublishedMatch` performs its own viewer authentication when applicable and a separate replay-access check. All callbacks are explicitly injected: this package has no permissive default, in-memory authority, or provider dependency.

The TypeScript interfaces reference the existing Rust core wire DTOs in `apps/web/src/contracts`; these are type-only dependencies and introduce no browser runtime into this package. When those DTOs move to a shared core contract, update the imports rather than defining a second identity model. `SimulationSnapshot` binds both Senkei snapshots and MatchContext; `ReproductionAssets` retains the actual RulePackage and World needed to revalidate and reproduce. A real adapter must also retain and resolve any match-affecting extension referenced by those artifacts.

The unit tests use test doubles to exercise sequencing, identity checks, failure paths, publication boundaries and the requirements placed on a settlement adapter. They do **not** prove an actual authentication provider, authoritative core integration, durable atomic settlement, privacy policy, ranking fairness or end-to-end official Match.
