# Battlefield redesign verification

## Result

**Independent Battlefield acceptance: FAIL.** The final camera frames all three authored lanes and their direction, Pixel 3D treatment is visually consistent, mobile browser controls fit, and the replay path preserves actual state. The standard view does not show both bases together; jungle/camp hierarchy, entity-role identification, and final-build local event semantics remain incomplete. This assessment uses the seven Battlefield criteria in [Issue #5](https://github.com/yohn-jp/senkei/issues/5), not a substitute checklist.

This review covers the final production renderer revision `993ef563325727c2c54b7f602acbb200e9240d26`. The full real-WASM browser suite passed 10/10 on that build. I inspected its screenshots at 1920×1080, 1440×900, 430×932, 390×844, and 320×844. The capture and matched c9 comparison are [here](../evidence/battlefield/after-993ef56-default/) and [here](../evidence/battlefield/comparison-default-c9-to-993ef56.json); the full browser recording is [battlefield-capture.webm](../evidence/battlefield/after-993ef56-default/battlefield-capture.webm).

The default match is `next-ec0b022507f93ba918d4f49aa9f52136`, an actual local Core Worker/WASM result: attacker victory by base destruction at T211. The browser fetched WASM with HTTP 200. Its input SHA-256 is `7caf454d46379bedfa5f13b20552e8bff1c9b980d21f260aca8a3689c6331fde`; owner/public presentation digest is `52061e54902949ef5c5ad00c4555c390053b31c8e0a2cdf1c661150035c0c867`; final state digest is `a1b81b6b1d44dba12d6540c81b62b943d064f1751b7eb2438622bafa838145e9`.

The default and c9 captures have identical input, match ID, owner/public replay digests, final state digest, semantic ticks, and viewport set. All 35 common screenshots differ because the renderer/UI changed; the final run adds six mobile Timeline/Details screenshots. Exact screenshot equality is not an acceptance condition for this redesign.

Follow T50 also targets the selected visible Hero at the exact replay position XZ `(48, 32.32)` on all five viewport sizes. The UI uses the actual entity at T50; the renderer does not select a nearby or inferred target.

## Controlled event evidence

The default match has no tower-destruction, Hero-death/respawn, or active-skill event. Two compiled tactic snapshots supplied those states without changing the ruleset. The harness replaced only the real workbench `simulate` request's snapshot; the Core Worker/WASM generated the result. They are explicitly controlled verification inputs, not ordinary UI-created setups or canned replay responses.

The final 993 cue capture is at [controlled-cue-993ef56](../evidence/battlefield/controlled-cue-993ef56/), with its [c9 comparison](../evidence/battlefield/comparison-controlled-cue-c9-to-993ef56.json). At 1440×900 and 390×844 it covers Clash T6, Hero death T74, owner-only same-slot Hero respawn proof T94, tower destruction T96, neutral Monster respawn T103, and base destruction/end T228. The final 993 farm capture is at [controlled-farm-993ef56](../evidence/battlefield/controlled-farm-993ef56/); it covers active Hero skill T211 and time-limit draw T240 at both widths. A separate [focused local Follow capture](../evidence/battlefield/controlled-farm-993ef56-skill-follow/1440x900/skill-follow-t211.png) follows the visible F03 Hero at T211 and checks its camera target against that entity's replay position. The root comparison confirms identical input, match ID, owner/public replay digests, final state digest, semantic ticks, and viewports for the c9 and final 993 cue runs.

Earlier c9/da1 comparisons remain available in [controlled-scenarios.md](../evidence/battlefield/controlled-scenarios.md). Those images predate final tactical framing and mobile-label adjustments; the 993 images linked above are the final-build evidence used for criterion 4. Native/WASM structural parity for `result`, `replay`, and `owner_replay` is recorded in [native-wasm-parity.json](../evidence/battlefield/native-wasm-parity.json).
