# Domain Catalog producer

`senritsu::catalog::DomainCatalog` is the public, static view of a Senritsu `VerifiedRulePlan`. Call `DomainCatalog::from_verified_plan(&plan)` after package validation, then pass `canonical_json()` to a consumer. The Rust type is the versioned producer contract; its output includes `schemaVersion`, full RulePackage identity and a catalog digest.

The producer projects the package's finite symbol domains, observation fields, collections, entity field schemas, capability signatures, arbitration, transition effects, execution order, and logical CU schedule. It preserves package IDs and types. It does not store the current world state or an Enbu observation. Nested collection fields retain both their own visibility and the collection audience, so consumers must check both before displaying a value. `KnownnessContract` distinguishes a source that may not resolve from an enemy entity that is not currently visible and from a field that cannot be read.

Catalog serialization uses ordered maps and a fixed struct field order. The catalog SHA-256 covers its canonical JSON content, including the package identity and optional metadata extension digest. `CatalogCompatibilityKey` carries the package identity, catalog digest, and extension digest together for cache invalidation. The RulePackage digest remains the value computed by Senritsu; adding catalog metadata does not change it.

`CatalogMetadataExtension` fills metadata absent from the current `RulePackage` model. Its ruleset ID, version, and complete digest must match the verified plan. It can declare control scopes for exact package entity type IDs, capability versions/durations/rejection codes, and typed Behavior Profile fields, inheritance order, per-Hero defaults, deterministic Squad aggregation, and named presets. The extension receives its own stable digest, and the final catalog digest includes it. The validator checks field types and finite ranges, default and preset values, legal scopes, aggregation types, inheritance uniqueness, persistent capability references, and package references. The base catalog reports `NotDeclaredByRulePackage` when those sections are absent.

Scope names are never inferred from strings such as `hero`, `unit`, or `minion`. Without explicit metadata, capabilities retain `PackageEntity(typeId)` or `PackageDomain`. A `LaneLimitedMinion` annotation requires a package entity schema with a typed `lane` field. The current `RulePackage` type has no built-in Behavior Profile, capability version, effect lifetime, or rejection-code section, so the shipped `initial_package()` and `next_package()` catalogs accurately mark these parts as undeclared. Test-only extension fixtures exercise metadata validation; they are not presets declared by either package.

The catalog describes finite typed vocabulary and access conditions. Jinrei v0.1 parsing and execution are unchanged. A focused test compiles supported numeric and collection expressions and rejects ordered enum comparison, matching the existing type checker. No Enbu observation adapter, Jinrei Editor UI, Behavior Runtime, TypeScript client, or PR #7 world integration is part of this producer.

Focused coverage includes stable serialization and digest reproduction, package/extension identity mismatch, visibility and absence of runtime data, typed collection and capability metadata, Behavior Profile validation and invalidation, and Jinrei operator compatibility. Run `cargo test -p senritsu --lib`.
