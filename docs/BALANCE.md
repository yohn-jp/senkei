# BALANCE — 初期Senritsuの数値・相互作用・検証計画

## 1. 目的

この文書はSenkeiの新しいゲームシステムについて、**会話で合意した数値の初期値を失わず**、未決定の数値を今後のバランス調整で具体化するための管理表と検証方針を定義する。

ゲームルールは [WORLD.md](WORLD.md)、[BATTLEFIELD.md](BATTLEFIELD.md)、[UNITS.md](UNITS.md)、[COMBAT.md](COMBAT.md) を参照。これは現行のsenkei.initialの値を修正した証拠ではない。新しいルールセットを実装する際には、SenritsuのID・版・内容digestを変更し、既存のローカルPvE／Jinrei／Enbuと互換性を検査する。

区分：
- **合意済みの初期設計値**：現時点の出発点。数値を変える場合には明示した新たな設計判断・版変更が必要。
- **設計目標**：ゲームとして守りたいトレードオフ。固定倍率や保証勝率を意味しない。
- **未決定**：実装前の詳細設計と対戦シミュレーションで決める。仮値を「既存仕様」にしない。

## 3. 移動係数の合成（再現可能な算術）

移動速度の合成は積：

    speed = base_speed × terrain_factor × minion_vision_factor × squad_factor

ここではHero個人／Squadの base_speed を1.0と仮定し、**確定した3倍率だけ**を計算する。部隊の基準速度の決定、地形境界の扱い、ユニット固有能力は別途。

| Squad | Lane・視界なし | Lane・視界あり | Jungle・視界なし | Jungle・視界あり |
| --- | ---: | ---: | ---: | ---: |
| Solo (×1.00) | ×1.000 | ×1.200 | ×0.800 | ×0.960 |
| Duo (×0.95) | ×0.950 | ×1.140 | ×0.760 | ×0.912 |
| Trio (×0.90) | ×0.900 | ×1.080 | ×0.720 | ×0.864 |
| Quartet (×0.85) | ×0.850 | ×1.020 | ×0.680 | ×0.816 |
| Quintet (×0.80) | ×0.800 | ×0.960 | ×0.640 | ×0.768 |

同条件・同base_speedならQuintetの速度はSoloの0.8倍、SoloはQuintetの1.25倍。これを「移動時間が20%短い」と混同しない（同距離所要時間は速度の逆比）。

Jungle×0.8にMinion視界×1.2をかけると×0.96となる。**視界があってもJungleの速度不利は残る**。両陣営が同じ視界を持っていても、敵Minionの視界によって自軍が補正されることはない。

移動速度の計算とJinreiの論理CU、時間当たりのゲーム内資源コストは別。速度アップが自動でCU消費を下げるわけではない。

## 4. 大規模Squadの強さと弱さ（設計目標）

### 集結の利点

- Heroが多いほど攻防・護衛・回復・制圧・連携スキルの効果を高められる。
- 連携成熟度と位置関係が整ったとき、総戦闘力が人数比例以上に高くなることを目指す。
- 同じ拠点への火力集中で、局地戦を短期で制する戦術が成立する。

### 集結の機会費用

- 人数が増えるほど遅くなる（合意済み係数）。
- 連携成熟に時間が必要で、急な合流では最大性能が出ない。
- 5体を1か所に置くと、ほかのレーン／ジャングルの視界・経験値取得・施設保護の分散が難しい。
- 複数の中立地点を同時に攻略できず、攻守の転換に移動時間を要する。
- 死亡時は人数が減って連携上限が下がる。一方、速度は人数が少ない値に切り替わるため、離脱の戦術的影響を総合評価する。

**重要**: 5体Quintetの具体的な「2.1倍」等は以前の説明用サンプルであり、採用した公式値ではない。固定倍率は未確定。単純な全ステータスの一括乗算だけにすると、Quintet以外が死にやすいため、能力・隊列・時間に基づく連携効果とする方向。

## 5. Solo／分散の選択理由（設計目標）

Soloを有利にするための無条件攻撃倍率は**現時点で合意されていない**。まず下記の既存の意味的な優位で価値を作る。

- 最高の人数別移動倍率、隊列形成不要による即応性。
- Heroを5つの場所へ分散させることでの視界・レーン・中立地点の同時カバー。
- 単独で資格を得た経験値は等分されず集中し、レベルとスキル取得の進行が速くなる。
- Minion視界に沿った俊敏な経路選択、敵Squadとの直接戦闘の回避。
- 必要ならJinreiが合流／分離を選択できるが、連携準備の機会費用が生じる。

**SoloとQuintetの優劣は同じマップ・同じ状況で固定されない**ようにする。見せかけの「Soloボーナス」を先に足すのではなく、複数目標・情報・移動・経験値による自然なトレードオフを検証する。

## 6. 経験値バランス

イベント報酬XPに対し資格のあるHeroが n 体なら、原則 XP / n を均等配分する。

| 資格Hero数 | 100 XPの例で各自が得る量 |
| --- | ---: |
| 1 | 100 |
| 2 | 50 |
| 3 | 約33.33 |
| 4 | 25 |
| 5 | 20 |

100 XPは**分配を示すための仮の報酬**であり、MinionやMonsterの既定報酬ではない。実際は決定論的な整数／固定小数点精度と剰余の規則をSenritsuで定義する。

分配資格はSquad人数・近接距離・最後の攻撃者だけから恣意的に決めず、別の型付き条件として固定する。資格を満たす複数HeroがSoloで別Squadに所属していても、同一イベントの資格者であるなら均等分配する。

**想定リスク**: Soloで安全にXPを稼いでレベルが先行し、集団戦ボーナスよりも強くなるケース。逆にQuintetが安全な周回を独占して5Hero全員を育てるケース。対象資格・報酬・ジャングルの難度・移動コストを同じテストで検証する。

## 7. Hero Catalogのバランス対象

初期12体は [UNITS.md](UNITS.md) の F01–F06／R01–R06 の3軸属性を基に定義する。各Heroの固有名・具体スキル・数値はまだ定まっていない。

| 評価軸 | バランス上の要求 |
| --- | --- |
| 配置適性 | 前衛6／後衛6。配置を拘束する属性ではない |
| 戦闘役割 | 防御・火力・支援がそれぞれ選ぶ理由を持つ |
| 戦術特性 | 強襲・制圧・遊撃・偵察・継戦・指揮が戦場行動に作用する |
| Solo適性 | 単独で選ぶHeroが存在しつつ、Solo専用を強制しない |
| Squad適性 | 複数のHero組合せで実際の能力連携が生じる |
| 情報と視界 | Scout型の寄与をDPSの大小だけで評価しない |
| Growth | レベル進行と編成時のSkill Treeで同Heroに戦術選択がある |
| Counters | 単一のHero／Squad／Skillがすべての戦況で支配的にならない |

異なる5種類のHeroを選ぶ場合の組合せは12C5=792通り。ただし重複選択可否は未確定なので、これをゲーム上の全戦型数と断定しない。Squad分割は人数パターンだけで7通りであり、Heroの割当・配置・陣令戦術・成長経路を含めれば組合せはさらに広がる。**組合せの多さはバランスの良さの証拠ではない。**

## 9. 決定論的なバランス検証の進め方

**同じ戦型・同じ敵・同じ初期状態を100回実行しても、勝率の標本は増えない。** 完全決定論のSenkeiでは、複数の異なる相手、初期配置、スキルツリー、ジャングル進軍、視界状態を含む**シナリオ集合**に対して比較する。

推奨評価軸：
- 勝敗・終局Tick・塔／本拠地残HP。
- 各レーンの戦線到達Tick、レーン間の移動時間。
- Squad人数履歴、連携成熟の滞在時間、死亡・Solo復活・合流回数。
- 各Heroのレベル推移、獲得資格人数、XPの配分と報酬の出所。
- Minionが提供した視界面積・現在の観測範囲・視界による移動優遇の継続時間。
- 中立キャンプ占有と討伐の時間、同時目標達成数。
- 戦術CU（論理）と実CPU・メモリ（物理）を**分けて**測定する。
- Hero属性別の有用性、編成パターン別の極端な支配を検査する。

### 必須の比較シナリオ

1. Solo 5体 vs Quintet、および2+2+1／3+2／4+1の組合せ。
2. Minionの視界を確保した経路 vs 情報を失った経路。速度係数の4地形・視界ケース。
3. ジャングル集中とレーン防衛・塔攻略の交換。
4. 経験値のSolo集中 vs Squad分割、レベル差が集団戦に与える影響。
5. 準備済みQuintet vs 合流直後のQuintet、連携成熟の価値。
6. 前衛・後衛・偵察・指揮・継戦の属性の異なる組合せ。
7. 死亡／復活直後のSoloと再合流、死亡によるSquad減員。
8. 観測不能な敵と三値のunknownを含む戦術分岐。
9. 無効な合流や発動不能スキル等、失敗時の標準行動。
10. 攻守を入れ替えた対称ケース、同時致死・同時塔破壊。

評価は勝率のみでなく、**戦略上の選択に実際の結果差が出るか**を見る。戦型の一般的な強さを論じる際はシナリオ集合の前提とHero分布を明示する。指標の数値合格基準は基準ケースと初期Senritsuの実装後に設定し、根拠のない「50%に収束」の目標を約束しない。

## 10. 調整と検証の制約

- 係数の変更はSenritsuのRulePackageに版と内容digestを与え、過去試合・Replayの意味を不意に変えない。
- Jinreiの三値論理、宣言順非依存、ordered評価、Costed IRとCUの契約をバランス変更の都合で書き換えない。
- Enbuの同時性・決定論を維持し、戦闘処理順の偶然で攻撃側に有利を与えない。
- Pixel 3DとSmooth 3D、FPS、LOD、GPU性能によって戦闘結果やHeroの移動倍率を変えない。
- SenkeiのローカルPvEテストは制限せず、将来のレーティング公式戦・チケット制度は別スコープ。
- バランス検証の結果には「確定したルール版」「比較した戦型」「実施した試験ケース」「未検証項目」を明記する。

## 11. 次の受入条件

合意した係数・5Hero固定・初期12Heroの属性・XP等分・Solo復活を**新Senritsuのバージョン付き仕様**に落とし込み、各項目をテストで検証できること。未決定値を埋める際は個別の設計判断とバランス根拠を記録し、リプレイ／Jinrei／Enbuと互換性を照合すること。

**この文書のコミットだけでは新ゲームルールの実装やバランス改善が完了したことにならない。**
