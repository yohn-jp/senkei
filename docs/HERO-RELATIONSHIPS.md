# HERO-RELATIONSHIPS — 信頼・関係グラフ・会話と連携

## 1. 目的と責務

Hero同士が共闘して関係を築くことを、物語だけでなく編成・戦闘の価値につなげる。**関係性による実際の連携ボーナスを認める**。物語・外観だけに限定する以前の提案は採用しない。

本書は合意した方向の設計正本であり、機能の実装完了を意味しない。Hero、Squad、合流・分離・死亡復活は [UNITS.md](UNITS.md)、行動解決は [COMBAT.md](COMBAT.md)／[BEHAVIOR.md](BEHAVIOR.md)、装備との役割分担は [EQUIPMENT.md](EQUIPMENT.md) に従う。既存G2の受入範囲へ、この文書だけで未実装機能を自動追加しない。

## 2. 三つの状態を混同しない

| 層 | 内容 | 有効期間・用途 |
| --- | --- | --- |
| 永続的な関係 | 相手への信頼・印象、関係タグ、共闘・エピソードの記録 | 複数試合を通じた育成と物語 |
| 戦闘用の連携特性 | 双方の関係から決定論的に導出する協力能力 | その試合の不変入力に固定する性能条件 |
| 試合中の連携成熟 | 現在のSquad構成と合流後の経過等によって変わる状態 | Enbuが既存のSquad規則で更新する |

永久の関係が深くても、合流距離、行動合法性、隊列、死亡、Solo復活の制約を飛び越えない。関係値の追加は、試合中の成熟を常時最大にする許可ではない。死亡や分離で試合中の成熟が変わっても、永続的な信頼を自動消去しない。

## 3. 非対称な感情と対称な戦闘用連携（採用方向）

Hero AからBへの信頼・印象と、BからAへの信頼・印象は別に持てる。一方的な敬意、警戒、対立、ライバル関係を表現できる。高い信頼が、仲の良さや価値観の一致を意味するとは限らない。

戦闘で使うペアの連携値は双方の情報から**対称かつ決定論的に導出**する方向とする。同じ二人について入力順・編成表示順を交換しても戦闘用の値は変わらない。平均、最小値、重み付き合成等の具体的な導出式・範囲・丸めは未決定。

関係モデルは信頼の値だけでなく、関係タグと進展の出来事を併せて扱う方向。独立した好感度・対立度等の数値ゲージを無制限に増やさない。未定義の関係を既存の敵観測Unknownと混同せず、初期値・欠損の扱いは関係定義側で決める。

## 4. 既存Squad連携への反映

**基礎は連携成熟の高速化、重要な関係には固有連携を追加する方向**を採用する。

- 信頼のある組み合わせは、合流後に協力体制を整えやすい。既存のSquad成熟処理へ反映し、別の競合する連携エンジンを作らない。
- 特定ペアには固有エピソードと結びつく連携能力を定義できる。全ペアへの新スキル作成は必須ではない。
- 基礎評価は、Squad内のペア数で正規化した平均的な信頼を使う方向。関係値の単純総和で、人数が増えるほど無制限に効果が増える方式を採用しない。
- 固有ペアの条件付き効果は基礎集約と区別する。同じ効果の多重適用・重複ペア・重複Heroの扱いは明示的な仕様を必要とする。
- 既存の人数別移動倍率、人数・時間による連携効果を、この追加だけで置き換えない。重ね合わせ、上限、減衰、Soloの基準は詳細設計で確定する。
- 戦闘参加に高信頼を必須とせず、未育成のHero構成も試せる。低信頼だけを理由にJinrei命令を無断で無視させる仕様は追加しない。

固有連携の対象、発動距離、同じSquadが必要か、Cooldown、Jinrei Capabilityとしての公開、受動／能動、消費、取得条件は未決定。具体的なスキルや倍率を設計例から自動採用しない。

## 5. 関係グラフと編成

グラフのノードはHero、辺はHero間の関係。初期12 Heroでは異なる二人の組合せが66組となるが、すべてに長編会話や固有連携を用意する必要はない。

編成画面では、選択中の5 Heroについて、永続的な関係、現在計画するSquad内で有効な連携、まだ満たしていない固有連携条件を区別する。高信頼ペアを同じSquadにするか、役割や戦場配分のため分けるかを判断できるようにする。

方向付きの感情はHeroを選択した詳細で示し、対称な戦闘用連携は別の表示にする。グラフの線の太さだけで能力を断定せず、計算根拠と適用条件を説明できること。並べ替えやグラフ上の配置で効果が変わらないこと。

Heroの同種重複選択可否は既存Senritsuの契約に従う。永続関係はPlayerに属するHero間の有向レコードとして保存し、実際のHero identityのProducerを参照する。Hero種類を所持個体や編成slotのidentityに読み替えない。

## 6. 育成・会話・エピソード

共闘、戦役での出来事、固有エピソード等から関係が進展する方向とする。何戦で何点増えるか、敗北・死亡で減少するか、同一試合の反復をどう扱うかは未決定。単なる同じNPCの反復回数だけを唯一の育成手段として固定しない。

会話は日常の掛け合い、実戦の確定イベントに対応する短い台詞、関係を掘り下げる固有エピソードに分けられる。固定台本と条件分岐を基本候補とし、ランタイムLLMを必須にしない。台本や発話者の価値観は個別キャラクター設定に従い、名前だけで性格・過去を創作しない。

関係進展に応じて会話、関係タグ、エピソード、演出、選ばれた固有連携へ接続できる。ガチャで特定装備を引くことを、関係エピソード全般の必須条件にしない。性能の獲得条件と会話の閲覧条件は区別して定義する。

Replayの再生・シーク・再閲覧だけで関係値や取得済みエピソードを再加算しない。戦後の関係更新と戦闘中の表示を分ける。保存・報酬確定の具体的な権威やオンライン方式は保留したままとする。

## 7. Snapshot・Catalog・認可

- 関係定義、導出規則、実戦に影響するペア値・取得済み連携は、版付きSenritsuとその試合の不変入力に結びつける。現在のプロフィールを読み直して過去の結果を変えない。
- 関係値・固有連携の変更は適合性とPreflightへ反映する。公開Capabilityや型が変わる場合はCompileの互換性も検証する。
- Enbuが連携の成立と効果を決める。Rendererの近接演出、台詞、アニメーションからボーナスを発生させない。
- 認可済みTraceでは、成立した連携・不成立理由を説明できるようにする。敵の非公開関係履歴・エピソード・予定行動は公開Replayへ流さない。
- 発話と会話条件もFogを守る。未観測の敵や隠れた橋の破壊を、台詞で先に知らせてはならない。

## 8. 受入観点と未決事項

検証時には、同じ装備・同じ関係・同じ入力のNative／WASM一致、A/B順序交換の対称性、Squad並び順非依存、人数増加時の集約、合流・分離・死亡・Solo復活との整合、過去Replay不変、戦後更新の重複防止、会話からの非公開情報漏えいを確認する。

ゲーム性は、同じHero編成でも高信頼ペアをまとめる場合と役割のため分ける場合、成熟速度と分散機動の交換、装備差との相互作用を実測する。数値の強化があることを否定せず、どの編成でも一択となるかを測る。

**詳細未決**：信頼の尺度・増減、感情から連携への導出式、Squad集約の重み・上限・欠損、成熟への作用式、固有ペアとスキル一覧、戦力指標への反映、会話の具体台本・閲覧条件、保存単位。これらは実装者が無断で固定する値ではない。

## 永続化と固定入力

A→BとB→Aは別レコードとし、タグ・進展履歴は版付きデータとする。未定義値を0や中立へ変換しない。閲覧では進展せず、Replay再生や同じImportで進展イベントを重複適用しない。導出式・係数・丸め・上限・固有効果はSenritsuの版付き定義に属し、未承認値では発火させない。実戦の値はMatch開始前に固定し、Replayから最新Repositoryを読み直さない。
