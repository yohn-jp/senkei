# 製品ビジョンとプレイヤー体験

## 1. コンセプト（確定）

Senkeiは、**自分が書いた戦略が自分の代わりに戦う**ゲームです。MOBAの3レーン、ミニオン・塔・本拠地という戦線構造を借り、試合中の反射操作ではなく事前の軍備設計、戦略、戦術アルゴリズムの設計力を競技の中心に置きます。

プレイヤーは兵科・兵数・配置・出撃順序・増援と撤退、対象選択、状況ごとの条件分岐を自作します。戦闘中に操作は行いません。戦闘結果を解析してAIを改善し、再戦することがゲームの主ループです。

プログラミングを学ぶための教材を前面に出すのではなく、戦略ゲームとして面白く、試行錯誤の過程で条件分岐、状態、データ構造、計算量、デバッグ、回帰テスト、汎化などを自然に学べる設計です。

## 2. ターゲット（方向性）

- ブラウザで気軽に戦略ゲームを遊びたいプレイヤー。
- RTSの判断は好きだが、操作速度やリアルタイム拘束は避けたい層。
- 自分の戦術やAIを作り、検証・改善することが好きなプログラミング／論理パズル層。
- 高度なプログラミング経験は参加条件としない。プリセットとノーコードにより開始障壁を下げる。

市場規模や売上の見積もりは確定していません。教育効果・収益性・リテンションを事実として断定しません。

## 3. 初心者から上級者への連続した体験（確定）

1. 初回は理解しやすいプリセット戦術でNPCに挑戦する。
2. 戦闘は完全自動。勝敗・戦線・実行された戦術を観察する。
3. 敗因を把握する。例：援軍の条件が成立しなかった、MIDに兵力が集中しすぎた。
4. ノーコードで条件を追加、あるいはテキストでコードを修正する。
5. 同じ条件で再実行し、変更前後の差異を検証する。
6. 新しい敵・編成・制限に対する汎化を試す。

プリセットは参加の入口であって強制的な戦術の型ではありません。プレイヤー独自の戦術設計を中心に置きます。

## 4. 主要画面・機能（初期目標）

- 戦場・3レーンの状態表示：戦線の押し引き、塔、部隊、拠点、時系列。
- 軍備・配置エディタ：兵科、数、レーン、初期配置、出撃・生産の構成。
- 戦術エディタ：ノーコードとテキストの二つの編集面。いずれも同じ表現を操作。
- PvEキャンペーン：簡単なシナリオから高度な条件分岐へと学べるNPC。
- 戦闘実行・リプレイ：停止、速度変更、任意Tickへの移動。
- デバッガ：発火条件、命令、値、状態、CUを確認。
- プロファイラ／ベンチマーク：CU内訳・勝敗・損耗・突破速度の比較。
- 戦術の保存と履歴：過去バージョンとの差分、回帰テスト、復元。
- 戦術のインポート・エクスポート：ローカルで共有可能な形式。URL公開やForkはオンライン追加機能。

## 5. UX原則（確定）

- 敗北を次の改善行動につなげる。事実として計測した原因と、推定上の敗因を区別する。
- 高度な能力のためにコードを書くことを強制しない。GUIとテキストは同一の意味論・命令集合。
- コード編集時にも静的エラー・CU見積もり・実行トレースを確認できる。
- PvEの実行回数を制限しない。ランク戦のチケットをローカルの学習・開発に持ち込まない。
- 対戦中のプレイヤー介入は必要としない。

## 6. 非目標（ローカル第一段階）

- 認証、アカウント、課金、広告、公式レート、チケット、対人マッチング。
- 常時接続、同期PvP、マルチプレイヤーの操作入力。
- サーバー上での無制限シミュレーション提供。
- 任意の外部JavaScriptを戦術としてサーバーで実行すること。
- 全兵科数・具体的な能力・試合時間をこの段階で固定すること。
