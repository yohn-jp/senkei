# COMBAT — 戦闘・移動・成長・Skill・Squad遷移

## 1. 目的と境界

この文書は初期の次期Senritsuに必要な**基本戦闘の意味と、Heroの成長・Squad連携・死亡復活の関係**をまとめる。数値・演算式の未確定部分を自動的に仕様値としない。戦場は [WORLD.md](WORLD.md)、個体とSquadの構成は [UNITS.md](UNITS.md)、数値表・評価は [BALANCE.md](BALANCE.md) が担当する。

Senritsuは何が攻撃可能で何が起こるか、移動・攻撃・死亡・XP・スキル・撤退・追撃の**ルールを定義**する。Jinreiは公開された観測から**Intentを選択**する。Enbuはそのルールに従って**同時刻の状態遷移を決定論的に確定**する。Rendererは許されたPresentationReplayから結果を描画し、当たり判定やダメージを再計算しない。

Jinreiの表層構文は [JINREI-GRAMMAR.md](JINREI-GRAMMAR.md) の宣言的なstate/action/when/do・三値評価を正本とする。以下の「自動攻撃」「追撃」「再編成」は戦律の行動概念であり、独自の新構文を勝手に追加する指示ではない。

## 2. 基本戦闘：射程内の敵を原則として自動攻撃（合意）

- UnitはSenritsuで定義された通常攻撃Capability、攻撃可能対象、射程、攻撃間隔等を持てる。
- **射程に入り、攻撃可能で観測できている敵Unitを、通常行動として原則攻撃する。** 塔・本拠地の対象条件もSenritsuが別途規定する。
- 毎回の通常攻撃命令をJinreiから発行する必要はない。ユーザーが編成と基本AIだけでも演武を見られることを保つ。
- Jinreiは攻撃対象の優先変更、特定対象への集中、交戦条件の変更、撤退、追撃、スキル使用などの**高度な判断**を行える。
- JinreiがIntentを発行しても、射程・視界・クールダウン・リソース・Capabilityが不合法ならSenritsu/Enbuで拒否される。Jinreiがワールドを直接変更することはない。
- Jinreiの評価条件がfalseまたはunknownなら、そのactionからはIntentを生成せず、Senritsuが規定する既定行動を適用する。

複数の敵を攻撃できる場合に「近い敵」「塔を攻撃中の敵」「最も弱い敵」のどれを優先するかは未確定。**ターゲット選択に同順位が発生する場合も、stable ID等による明示的な全順序が必須**。HashMap順・実行側の順番・乱数で解決してはならない。

射程、見えていること、狙えることは別の判定。Fog of WarのUnknownを、攻撃可能な既知の対象として扱わない。例外的に視界外へ効果を与える能力を追加する場合は、SenritsuのCapabilityと対象座標・視界制限に明示する。

## 3. Default Behavior（設計方針）

Jinreiのルールが不足していても試合は進行する。**Senritsuが定義する標準行動**があり、必要ならJinreiのIntentでその方針を調整できる。

| 戦場状態 | 既定行動の方向性 |
| --- | --- |
| 射程内に合法な敵がいる | 攻撃間隔・状態を満たせば通常攻撃 |
| 合法な敵がいないが、移動目標がある | 現在の移動目標へ進軍 |
| 移動目標も合法な対象もない | 待機または保持など、Senritsuの基本行動 |
| 明示的なJinrei Intentがある | 命令の有効性・優先度・競合を検証して反映 |
| 命令が不成立 | 定義された拒否理由を記録し、既定行動へ復帰／継続する |

この表は行動の存在と責務の方向を示す。自動的な塔優先・Hero優先・Minion優先・進軍経路・行動対象の詳細は未確定。

## 4. 追撃・撤退（合意）

追撃・撤退は**Senritsuの移動・交戦Capabilityと遷移規則**。プレイヤーはJinreiのstateとactionで「どの状況で追撃／撤退するか」を設計する。

- 追撃の対象や経路は視界と通行制約を満たす必要がある。最後に観測した位置を現在の敵位置だとみなさない。
- 撤退の地点は自軍拠点、味方塔、指定地点、隊列の後方などの合法な移動目標としてSenritsuに定義する。
- Minionの自動追撃がレーンから無制限に離れないよう、既定行動に追撃範囲・帰還条件等を設ける必要がある。
- Squadの追撃・撤退はそのときの**一体の部隊としての進路**に基づく。部隊から勝手にHeroが離れず、離脱は死亡または合法なJinrei分離Intentで処理する。

追撃の終了条件、移動中の攻撃可否、交戦距離、撤退状態による耐久や速度変更、塔・中立モンスターの索敵と追撃の特別規則は未確定。

## 5. Hero / Squad移動の合成規則（合意）

移動倍率の基本：

    effective_speed = base_movement_speed
        × terrain_factor
        × friendly_minion_vision_factor
        × current_squad_size_factor

- 地形係数：Lane ×1.00 / Jungle ×0.80。
- Minion視界係数：味方Minionの現在の視界内 ×1.20、そうでなければ ×1.00。複数視界の重複加算なし。
- 人数係数：Solo ×1.00 / Duo ×0.95 / Trio ×0.90 / Quartet ×0.85 / Quintet ×0.80。
- Sprint等のHero固有移動スキルや減速効果を導入するなら、順序・上下限・重複・無効化をSenritsuで版付き定義する。まだ固定しない。

Squadは一つの集団移動の目標・隊列を持つ。個々のHeroが異なる移動能力を持つ場合に、部隊の基準速度をどう選ぶかは未確定（例：最も遅いHeroへ合わせる案）。隊列の横幅と通路幅、地形境界、複数Heroが違う地形上にいる際の扱いも決める必要がある。これらは視覚演出の都合ではなくSenritsuの物理的な判断である。

## 6. Squad連携：人数と成熟時間（合意）

- 5体は固定の戦型資源。Squadの人数が増えるほど**連携戦闘性能を非線形に高くする方向**。
- Squadを編成・合流した瞬間に最大連携へ到達しない。**集結後に一定時間、隊列・位置関係を維持する**ことで成熟する。
- 成熟度は人数別の連携能力・護衛・攻撃集中・回復・妨害・指揮などへ影響する。単純に全ステータスへ人数倍率を掛ける方式だけに限定しない。
- Soloには人数連携ボーナスはないが、最速・即応・独立した観測／ジャングル攻略・XP集中がある。
- 部隊の分離はJinreiで明示し、死亡は自動離脱。合流／分離・死亡に伴う連携の再計算は、Senritsuに定める必要がある。

**未確定**: 連携係数の正確な曲線、成熟に必要なTick、隊列維持条件、合流直後の成熟度、人数減少時に過去の成熟を残すか、固有Heroの指揮Traitによる補正。

**現段階で推奨する検討案**: 成熟速度は人数・Hero能力で変わり、死亡による減員では残存人数の上限まで効果を切り下げ、合流／分離で新しい編成の成熟を始め直す。ただし合意値ではなく、[BALANCE.md](BALANCE.md) のシミュレーションで採否を判断する。

## 7. 経験値（合意）

**獲得イベントの経験値は、獲得資格のあるHeroへ均等分配する。** 資格のないHeroやMinionの数を分母に入れない。Squadの所属名簿と経験値分配人数を同一視しない。

    XP_per_eligible_hero = XP_reward / number_of_eligible_heroes

例：100 XPで資格のあるHeroが1／2／5体なら、各Heroの取り分は100／50／20 XP。これは分配則の説明であって、報酬100 XP自体は未確定。

- Soloで討伐した場合は経験値を独占でき、より早い成長経路を獲得できる可能性がある。
- Squadは討伐の安定性・護衛・連携に優れるが、複数Heroが資格を得ると個体XPが薄まる。
- 対象資格を判定する**距離、観測、参加、最後の一撃、死亡状態**などの詳細はまだ決まっていない。資格者の集合はSenritsuが確定する。
- レベルXPは整数／固定小数点等の決定論的な形式で保持し、端数配分・除算・オーバーフローを仕様化する。単に画面表示の浮動小数点で加減算しない。
- 報酬源はMinion撃破、中立モンスター討伐、塔等が候補だが、正確なイベントと報酬値は未確定。

経験値イベントはEnbuの規則解決に従い一度だけ確定し、レンダラーは経験値の付与やレベルアップを再計算しない。

## 8. レベルアップ・Skill Tree（合意）

- レベルアップにより**Heroの基礎ステータスが向上**する。
- Heroはレベルに応じて**複数のスキルを獲得**できる。
- スキル取得・成長の**経路は編成時に設定**する。リアルタイムプレイヤー操作で選ぶ仕組みにはしない。
- 戦闘中は、Senritsuが前提レベル・前提スキルを満たしたときに、選択済み経路を解釈して取得・強化を解決する方向とする。
- アクティブスキルはJinreiが合法な対象・タイミングを判断してCapabilityを発行できる。パッシブスキルはSenritsuの定義に基づいて動作する。
- 未使用能力について、どこまでDefault Behaviorが自動発動するかは未確定。戦術を一切書かないとゲームが停止しないことと、強力なスキルの最適な自動発動を無料提供することは別。

Hero Catalogには基礎攻防／HP／速度／射程、成長プロファイル、スキルツリー、クールダウン・コスト・対象制約・効果、Heroの属性と組合せ条件をデータとして持たせる。Senritsuの有限な遷移プリミティブで表せない新効果は、Enbuの拡張と互換性の定義が必要。

スキルの通常攻撃との併用、アニメーション時間、詠唱・中断、重ねがけ、範囲・持続効果、Skill Point制・最大レベル・最終取得順はまだ固定しない。

## 9. 死亡・復活・再編成（合意）

1. HP等の致死条件が成立したHeroは死亡し、**その時点で所属Squadを自動離脱**する。
2. 残されたSquadは人数が一つ減った状態で行動を継続する。Quintet→Quartet等、速度倍率と連携状態を更新する。0体なら解消。
3. 死亡HeroはSenritsu所定の**復活クールタイム**を消化する。
4. クールタイム後、自軍の**本拠地で必ずSoloとして復活**する。元のSquadへ瞬間合流・自動配属はしない。
5. 合流は、Heroが別の味方Squadと同じ位置（Senritsuが定義した合流可能範囲）まで移動し、Jinreiの合法な合流Intentがある場合だけ実行する。
6. 戦闘中の任意分離もJinreiの合法な命令で行える。死亡の自動離脱とは別の操作である。

復活までのTick、死亡後XPの資格、復活時のレベル／取得スキル保持、復活HP、無敵時間、同時に複数Squadへ合流する競合時のルール等は未確定。合意したSolo復活を変える「自動元Squad復帰」は導入しない。

## 10. 決定論的Tick／イベント解決（既存アーキテクチャの遵守）

既存 [ENBU.md](ENBU.md)、[SIMULATION.md](SIMULATION.md)、[JINREI-GRAMMAR.md](JINREI-GRAMMAR.md) を維持する。

1. 同じ確定Tickから両陣営が観測可能な状態を生成する。
2. Jinreiのstate/actionを論理的に同時評価し、IntentとCUを確定する。
3. Senritsuの全順序と合法性に基づいて競合を調停する。
4. 移動、交戦、被害、死亡、経験値、レベル、スキル、施設、本拠地、視界、復活等を**規範的なフェーズ**で解決する。
5. 次Tickのワールド／イベント／終局を確定し、Replayと認可された診断を生成する。

上記4の**詳細な内部順序は未確定**。特に「致死Tickで攻撃していたHeroの攻撃が成立するか」「経験値付与前に死亡したHeroは対象か」「死亡でSquad倍率が変わるのはいつか」「視界を得たTickに速度優遇するか」は戦術的影響が大きいため、実装前に明示し、対称性・同時性をテストする。攻撃側を先に丸ごと更新するような隠れた順序は避ける。

## 11. 数値処理・CU・観測

- 戦闘は**完全決定論**。命中ダイスやドロップ乱数を初期戦闘モデルに混入させない。
- HP、距離、速度、経験値、レベル、クールダウン等は整数／固定小数点など版付きの確定演算。
- 転倒、死亡、対象消滅、視界喪失時は安定した同順位規則を用い、エラーまたはSenritsu既定行動へ明示的に遷移する。
- 観測できない敵HP／位置はJinreiのObserved<T>/Truthに従いUnknownを返す。未観測を「いない」「0体」とみなさない。
- 移動速度や戦闘技能の倍率と、戦術プログラムが消費する**論理CUは別資源**。CUはCosted IRの固定論理操作で算出し、エンジンの物理最適化で変えない。

## 12. 受入テストとして必要な対戦ケース

| ケース | 保証内容 |
| --- | --- |
| 通常交戦 | 命令なしでも合法な射程内対象へ通常攻撃 |
| 複数対象 | タイブレークを含む対象選択の全順序 |
| 視界なし | 観測不能な敵への不正な追撃・Target Intentを拒否 |
| 撤退 | Jinrei Intent→Senritsuの意味→Enbu状態遷移 |
| Squad移動 | Solo〜Quintet、地形・Minion視界の速度倍率が合成される |
| 合流と分離 | Jinreiが選択した合法なSquad操作だけを適用 |
| 死亡 | 即時のSquad自動離脱・連携と人数倍率の再計算 |
| 復活 | クールタイム後の拠点Solo復活、元Squadへの自動復帰なし |
| XP | 資格Heroがn人なら同じXPを等分、同時イベントと端数処理が再現可能 |
| レベル | 基礎ステータス上昇、事前スキル経路に従った自動取得 |
| 交戦と同時死亡 | 両陣営に隠れた先攻有利がない |
| Replay | 戦術内部や敵の非公開状態を出力しない |

実装での具体的な攻撃・防御・射程・XP曲線・スキル個数・復活時間・連携倍率は、次期Senritsuの検証済みRulePlanとして後続の詳細仕様とともに確定する。現在のsenkei.initialの数値を、今回の議論で決めたものとして扱わない。
