# 戦場とゲームプレイルール

## 1. 確定したゲームループ

1. 兵科・兵数・施設や拠点構成を予算／ルールに従って設計する。
2. TOP / MID / BOT の3レーンへ兵力・初期位置・出撃順・生産／増援方針を自由に割り当てる。
3. 全軍、レーン、部隊、ユニットの各スコープに、条件付き戦術を設定する。
4. 完全自動かつ乱数を使わない戦闘を実行する。
5. 勝敗とトレースから原因を検証し、構成・戦術・CU使用を改善する。

標準的な勝利条件は敵本拠地の破壊。3レーンの多数決ではありません。PvEの特殊条件はシナリオ定義で指定可能とします。

## 2. 3レーンと戦線（初期Senritsuで確定）

- TOP / MID / BOT の3レーンが存在する。
- 戦線はプレイヤーの介入なしに進行する。ユニット・塔・施設と拠点を扱う。
- 各レーンの兵力と戦術は独立に設定でき、全軍戦略によって統合制御もできる。
- レーン間の増援、移動、攻勢／守勢の切り替えを表現可能にする。
- 兵力配分と計算予算配分はトレードオフを生む設計対象とする。

「初期に一括配置するか」「兵舎から定期出撃するか」「動的に増援するか」を固定のプリセット選択に限定しません。プレイヤーが戦術で選択できることを目指します。ただし、最終的に可能な出撃・生産機構はゲームルールとして有限・検証可能な操作集合で定義します。

## 3. 軍備と配置（確定原則／未決定詳細）

プレイヤーは兵科、数、装備や施設（採用する場合）、前後配置、レーン配分、部隊編成、出撃順序、出撃タイミング、生産や増援条件を設計します。戦術プログラムは味方の行動を制御します。

以下は**兵科候補の例**であって確定したクラス・数ではありません。

| 例 | 役割 |
| --- | --- |
| 重装兵 | 戦線維持、前衛保護 |
| 歩兵 | 標準的な攻防 |
| 射手 | 射程による火力 |
| 騎兵 | 機動、突破、奇襲 |
| 攻城兵 | 塔や施設への攻撃 |

兵科の性質は単純な相性倍率だけではなく、射程・移動速度・攻撃間隔・対象優先度・衝突・配置・タイミングで表現する方向とします。具体的な能力値、数量、建築コストは別途設計します。

## 4. 戦術ロジックの粒度（確定）

- 戦略：全軍の資源再配分、レーン重視、フェーズ変更。
- 戦術：レーン・部隊の進退、増援、集中攻撃、目標変更。
- ユニット：特定条件での撤退、対象選択、能力使用（能力を採用する場合）。

複合条件、順序、優先順位、状態変数、複数レーンの観測を許容します。複雑なエッジケースの表現を人工的に禁止せず、有限な命令集合と計算予算で制御します。

例：MIDで敵攻城兵が多く、予備兵が十分で、TOPが優勢であり、直近の増援が一定期間発動していない場合にTOPからMIDへ移送する。

## 5. 勝敗の意味（確定）

- 同じ盤面、同じ両者の編成、同じ戦術・状態・ルール版なら同じ結果。
- ダイス・命中判定等のゲーム内乱数を初期コアには導入しない。
- 戦闘はユニット数や強さの単純な一回の集計で終わらず、Tickごとの移動・交戦・損耗・戦術反応が結果を変える。
- 不確実性は主に相手の戦略の非公開部分、戦術相性、読み違いから生まれる。
- 同点・時間切れ・相打ちなどはルールとして明示し、黙示の乱数で解決しない。

## 6. 未決定のゲームバランス

- 各兵科・施設の確定リスト、移動・攻撃モデル、リソース配分と合計上限。
- 生産／出撃の制約、兵舎と塔の性質、レーン間の移動グラフ。
- 交戦の距離・衝突・範囲攻撃・回復等の採否。
- 戦闘時間、Tick間隔、最大ユニット数、時間切れルール。
- 攻撃と防衛で同じ軍備予算・資源を使用するか。
- PvEシナリオの具体的な勝利条件。

## 7. ゲーム仕様の置き場所

三レーン、兵科、出撃／生産、塔、本拠地、各種数値は**初期Senritsuのルール**である。Jinreiの構文やEnbuの汎用実行エンジンの仕様として固定しない。戦律は[ Senritsu設計](SENRITSU.md)に従ってバージョン管理される。

## 8. 次期Senritsuにおけるゲームの具体化（合意）

従来の説明はSenkeiの抽象的な三レーン戦闘体験であり、既存の小規模`senkei.initial`と最新ゲーム設計を同一視しない。次期Senritsuの具体的なゲームデザインを次の文書に固定する。

- **WORLD**：対角側の本拠地を持つMOBA型三レーン、レーン間ジャングル・中立モンスター地点、Minionの陣営共有視界と移動優遇。[WORLD.md](WORLD.md)
- **UNITS**：戦型へHeroを5体固定で採用、初期12種類（前衛6／後衛6）、三軸特性、Solo〜QuintetのJinreiによる動的再編成、死亡時自動離脱・拠点Solo復活。[UNITS.md](UNITS.md)
- **COMBAT**：射程内の敵への既定の通常攻撃、追撃・撤退・Skill使用の型付き命令、XPの資格Heroへの等分、レベルアップと編成時Skill Tree選択。[COMBAT.md](COMBAT.md)
- **BALANCE**：レーン×1.0／ジャングル×0.8、味方Minion視界内×1.2、Squad人数に応じ×1.00／0.95／0.90／0.85／0.80、非線形だが成熟時間を要する連携、Soloの情報・機動・XP優位。[BALANCE.md](BALANCE.md)

**戦闘中の操作はJinreiが自動判断**する。プレイヤーが戦況を見てリアルタイムにHeroを動かすことはない。Squadの任意分離禁止という古い案は撤回され、現在はJinreiの合法Intentによる合流・分離が可能（死亡離脱は自動）。追加の数値をこの概要で創作せず、未決定事項は各詳細文書に保管する。
