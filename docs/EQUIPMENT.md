# EQUIPMENT — 装備資産・性能ランク・戦力と戦略

## 1. 位置づけと適用範囲

本書は装備について合意したゲームデザインの正本。実装済み機能の報告ではない。装備とHero関係性は今後の拡張設計であり、今回の文書化だけで既存G2の実装・受入範囲へ追加しない。

Hero／Squadの基本は [UNITS.md](UNITS.md)、戦闘解決は [COMBAT.md](COMBAT.md)、数値と検証は [BALANCE.md](BALANCE.md)、不変入力とIdentityは [RUNTIME-INTEGRATION-CONTRACTS.md](RUNTIME-INTEGRATION-CONTRACTS.md) に従う。関係性は [HERO-RELATIONSHIPS.md](HERO-RELATIONSHIPS.md)、取得・市場・通貨は [REWARDS-AND-LIBRA.md](REWARDS-AND-LIBRA.md) へ分離する。

## 2. 装備に持たせる価値（合意）

**装備は局地的な戦闘・戦術に明確な性能差を生み、その差を戦場全体の戦略で覆せる余地を残す。**

- 同じHero・同じ局地条件なら、高ランク装備が低ランク装備より明確に強くてよい。すべての上位装備に必ず欠点を付け、横並びの交換条件だけにする必要はない。
- 装備収集・取得の成果は実戦性能に表れる。単なる外観、希少度表示、称号として代替しない。
- 一方で、正面で強い相手に対して、別レーンの攻略、目標交換、偵察、経路、局所的な人数差、分散と集結などの選択が意味を持つ戦場を維持する。
- 「戦略で覆せる」は、任意に大きな装備差を常に覆せる保証でも、低戦力側への隠れた補正でもない。許容する性能差と対戦条件は実測して決定する。

三つの責務を分ける。

| 要素 | 強さの所在 | プレイヤーの判断 |
| --- | --- | --- |
| 装備 | Hero個体の性能・得意な役割 | 誰に何を装着するか |
| Hero関係性 | 複数Heroの協力・連携成立 | 誰を組ませ、いつ合流させるか |
| Jinrei／戦型設計 | 上記の能力の運用 | どこで、いつ、何のために使うか |

装備はHero固有性を完全に置き換えるものではない。武器・防具・機動・偵察・支援等の効果カテゴリは候補であり、装着枠や具体的な能力値を本書で創作しない。

## 3. 恒久資産とランク（合意）

- 装備は戦闘で破壊されない資産。耐久度、修理、戦闘のたびの消失を導入しない。
- 同じ装備の重複を無制限に保有できる。ゲーム上の所持枠制限を設ける方針ではない。保存・表示は集約やページ分割等で扱えるが、有限の実装容量を無限と保証しない。
- ランクは装備そのものの性能段階を表す。ランク名、段階数、倍率、性能予算は未決定。
- 「+1、+2…」型の反復強化は設けない。ランクと別の細かな強化値を追加して複雑化しない。
- 進化・派生は採用可能な方向とする。上位ランクへの発展と役割の分岐を検討できるが、進化先、素材、重複消費、研究条件、可逆性は未決定。
- 戦闘参加・戦術の試験に資源を消費させない。資源・研究・内政の詳細は保留する。

装備の破損がないことと、任意売却・進化で所有状態が変わることは別。進化や売却の詳細が決まる前に自動廃棄・自動合成を実装しない。

## 4. レートと戦力

**レートは対戦実績、戦力は持ち込む編成の能力条件として分ける**方向とする。Jinreiの巧拙を装備性能に混ぜない。

装備だけでなく、実戦で有効になる関係性の連携効果も比較対象から抜け落とさないよう、戦力モデルの評価対象とする。ただし、信頼度と装備価格を単純加算した数式は採用しない。相性や条件付き能力を単一の数字だけで完全に表せるとは主張しない。

オンラインで戦力を再計算しても、装備取得・所有の正当性を証明したことにはならない。この二つは別契約。公式装備とローカル装備の分断方式を本書で採用せず、オンライン基盤・中央検証・取得権威の判断は引き続き保留する。

## 5. 実装に必要な既存アーキテクチャ上の境界

- 性能・装着適合性・進化による能力変更はSenritsuの版付き定義として扱い、UIや価格から戦闘値を導出しない。
- 戦闘で使う装備構成・定義の参照はMatch入力へ固定する。戦闘開始後の装備取得・売却・付替えで過去の試合や進行中Snapshotを変更しない。
- 戦闘に影響する装備構成の変更は関連するPreflightを失効させる。Jinreiの型・Capability等に影響するときはCompile互換性も再検証する。すべての外観変更でCompileを無条件に失効させない。
- 装備による実効果はEnbuが解決し、Rendererは認可された結果を表示する。装備プレビューと戦場で独立の能力計算を作らない。
- 将来の装備SchemaやSlot名は、現行APIが既に対応するものと表示しない。

## 6. 検証の考え方

局地性能と試合全体を別々に測る。

1. Hero、レベル、Skill、初期条件、Jinreiを固定し、装備だけを変えた局地戦で性能差を確認する。
2. 同じ装備差に対し、経路・目標・視界・Squad配分を変えた実Enbu試合を比較する。逆転例だけで一般的な均衡を宣言しない。
3. レーン、陣営、Hero役割、関係性、対施設戦を変え、装備の普遍的な一択化や過大な差を検出する。
4. Native／WASM、再実行、ReplayのIdentityと結果が一致することを確認する。
5. 売却・付替え等で既存Experimentが変化しないことを確認する。

数値の合格閾値、マッチング戦力帯、ランク別倍率は未決定。今回の方針を根拠に既存の戦闘数値を無断で変更しない。
