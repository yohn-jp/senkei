# PROGRESSION-UX — 装備報酬・市場・Hero関係性の画面導線案

## 1. 範囲と未確定事項

本書は [EQUIPMENT.md](EQUIPMENT.md)、[HERO-RELATIONSHIPS.md](HERO-RELATIONSHIPS.md)、[REWARDS-AND-LIBRA.md](REWARDS-AND-LIBRA.md) の合意を、操作できる体験へ接続する**合意用の設計案**。これらの機能が現在実装済み、または既存G2に追加実装する承認済みとは扱わない。

資源・内政・研究の詳細、EOS／GS2、中央コミット、取得権威、ガチャ頻度・確率・価格、関係増加式は保留する。UI都合で未決事項を決定しない。バックエンドが未選定でも必要な成功・未確定・失敗・復帰の区別は定義する。

X系IDは将来の論理的作業面であり、全て別URL・別モーダルにする指示ではない。現在のS00〜S15へ未稼働ボタンだけを追加することは禁止する。有効なデータと処理が揃った機能だけを入口に出す。

## 2. 戦後から装備を使うまで

~~~mermaid
flowchart TD
    B["S12 / S13 確定した試合"] --> R["X01 戦後の進展・報酬"]
    R -- 有効な抽選権利がある --> D["X02 ガチャ確認・結果"]
    R -- 装備を確認 --> I["X03 装備庫・装備詳細"]
    D -- 獲得が確定 --> I
    D -- 未確定／失敗 --> D
    I -- 採用を検討 --> E["X04 装着・編成差分"]
    E -- 明示適用 --> H["S05 / S07 同じ戦型Draft"]
    H --> P["S10 再検証"]
    I -- 売却／購入を検討 --> M["X05 マーケット"]
    M --> C["X06 注文・買取確認"]
    C -- 確定／取消／照会 --> M
    M --> I
    M -- 通貨統計 --> L["X10 Libra統計"]
    L -- 元の検索条件へ戻る --> M
~~~

ガチャを引くこと、装備を付け替えること、報酬画面を全て見ることを次の無料戦闘の必須条件にしない。戦後画面を後で確認しても同じ報酬・関係更新を再付与しない。

## 3. 装備・報酬・市場の画面契約

| ID | 主目的・表示 | 操作と戻り先 | 失敗・未確定時 |
| --- | --- | --- | --- |
| X01 戦後進展 | 元Match、勝敗、実際に確定した取得／関係変化、未確定項目 | 詳細、後で見る、分析、再戦 | 試合成功と報酬確定を別表示。未定義報酬は作らない |
| X02 ガチャ | 有効な権利・対象プール・提供される確率／保証・実行条件 | 抽選確認、結果一覧、演出スキップ、装備詳細 | 抽選要求と演出を分離。結果不明で再抽選させず状態照会へ |
| X03 装備庫 | 種類、ランク、保有数量、装着／取引中等の実状態 | 絞込、詳細、装着候補、売却候補、呼出元へ | 0件・絞込0件・読込失敗を区別。重複を勝手に処分しない |
| X04 装着差分 | 対象Hero／枠、現在装備と候補、性能差、装着適合性 | 比較、明示適用、取消→元の装備庫／Hero詳細 | 不適合理由を表示。未計算値を0や確定戦力にしない |
| X05 市場 | 売買対象、現在の注文／価格情報、保有と利用可能残高 | 検索、購入候補、出品候補、最低買取、注文状態 | 検索結果の価格を約定保証にしない。通信状態と取引状態を分離 |
| X06 取引確認 | 対象・数量・相手種別・価格／最低保証・採用済み手数料・受払総額・期限等 | 確認、取消、確定後の状態照会 | 古い価格・重複要求・残高不足・結果不明は成功扱いしない |
| X10 Libra統計 | 定義された累計発行量と集計範囲・更新状態 | 統計詳細、元の市場へ | 未取得値を0として描かない。売買高と発行を混同しない |

装備は破壊されず重複在庫は制限しない。表示の集約・ページ分割を所持制限にしない。保有数量と利用可能数量を分け、取引拘束中や装着中の扱いは採用した所有・取引契約に従う。取引や進化で元の装備を手放すときの影響を明示し、自動解除・自動合成は未承認のまま追加しない。

「プレイヤーへの出品」は買い手待ちであり売却完了ではない。「マーケットメーカーへの最低保証買取」は別の相手・確定条件を持つ。確認画面と結果でこの違いを隠さない。新規Libraの発行はマーケットメーカーのみ。出品やプレイヤー間約定を新規発行として計上しない。

装備変更は現在Draftへ明示適用し、過去Runや進行中Snapshotを変えない。戦力差の表示は利用する計算規則を明示し、マーケット価格を戦力値に代用しない。

## 4. Hero関係性から会話・編成へ

~~~mermaid
flowchart TD
    H["S05 Hero詳細 / S07 Squad"] --> G["X07 関係グラフ"]
    G -- ペアを選択 --> P["X08 ペア詳細"]
    P -- 閲覧可能 --> C["X09 会話・エピソード"]
    C -- 終了／中断 --> P
    P -- 組合せを試す --> S["S07 編成変更のプレビュー"]
    S -- 明示適用 --> R["S10 再検証"]
    S -- 取消 --> P
    P -- 元の選択と表示へ --> G
    G -- 呼出元へ戻る --> H
~~~

| ID | 必須表示 | 操作と境界 |
| --- | --- | --- |
| X07 関係グラフ | Heroの選択、方向付き信頼／感情と対称な連携の区別、編成中の対象 | 辺の選択は閲覧。選んだだけでHero／Squadを差し替えない。リスト形式でも全情報へ到達可能 |
| X08 ペア詳細 | A→B、B→A、関係タグ・経緯、導出された戦闘用連携、成立条件、会話の状態 | 連携は恒久関係・試合中成熟・未解放能力を分ける。計算根拠未定なら数値を作らない |
| X09 会話 | 発話者、内容、閲覧位置、必要な選択、既読／未読／中断 | 終了・中断・再閲覧を区別。戻り先は同じペアとグラフ文脈。任意会話の閲覧を戦闘開始の必須にしない |

関係グラフをドラッグ・色・線の太さだけで読ませない。MobileではHero選択→相手一覧／ペア詳細→会話を独立して操作できる。Desktopでは全体グラフから同じ情報へ移動する。キーボードでもペアを選択できる。

高信頼と友好的な感情は同義ではない。固有連携の解放と会話の既読は別の状態であり、再生／スキップ／シークだけで戦闘性能を重複加算しない。分岐選択の不可逆性や中断時保存は、物語側で採用した規則を事前に説明する。未決の選択効果を会話UIが創作しない。

戦闘中の台詞は認可された実イベントへ結びつける。未観測の敵位置・行動や橋の破壊を台詞で漏らさない。未解放エピソードの説明は必要条件を伝えつつ、未公開の物語本文を開示しない。

## 5. 合意を必要とする判断

| 判断 | 本書で固定しないこと | 決定前でも守るUX |
| --- | --- | --- |
| ガチャの権利・頻度・確率・保証 | 勝利1回につき1回、課金、天井等 | 有効条件だけ表示。結果の重複付与なし |
| 装着枠・重複利用・進化 | 個体管理か数量管理か、素材、進化先 | 適合性・影響・取消を示し自動処分しない |
| 市場の方式 | 固定出品／注文板、手数料、買取後の在庫 | 注文・約定・取消・結果不明を区別 |
| オンライン権威 | GS2／EOS／自作、オフライン取得の統合 | 実行場所から所有・確定を推定しない |
| 関係の成長と連携 | 尺度、増減、成熟への作用、固有効果 | 永続関係と試合中成熟、未計算を区別 |
| 会話の分岐・再閲覧 | 選択効果、スキップ時の記録 | 不可逆操作を事前表示し、再閲覧で再付与しない |

## 6. 将来拡張の受入シナリオ

これらは追加機能を実装する段階の受入であり、現在のG2未達件数へ混ぜない。

- UX-X01：同じ戦後結果を再閲覧しても報酬・関係変化を再付与せず、報酬を後回しにして再戦できる。
- UX-X02：抽選確定後の演出スキップ、結果表示前の再読込、通信結果不明で抽選を二重実行しない。
- UX-X03：重複装備の集約→詳細→Hero装着プレビュー→取消／適用で、在庫・Draft・過去Runの責務を守る。
- UX-X04：市場出品とマーケットメーカー買取の相手・保証・結果が区別され、価格変更時に再確認できる。
- UX-X05：注文状態の再照会で残高や在庫を二重増減せず、Libra発行数とプレイヤー間移転を混同しない。
- UX-X06：関係グラフ→ペア→会話→戻るで同じ対象・閲覧位置を維持し、編成を無断変更しない。
- UX-X07：連携のプレビューと明示採用、合流・分離・Solo時の適用範囲を区別し、再閲覧で性能が増えない。
- UX-X08：未解放・欠落データ・オフライン／未接続・未確定に、実際に使える次の操作がある。
