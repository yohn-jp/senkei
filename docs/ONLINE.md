# 将来の公式非同期PvP（ローカル版の範囲外）

## 1. 将来の体験（合意した方向性）

- プレイヤーが任意の相手を選び、事前に構築した攻撃戦略で挑戦する。
- 防衛側は拠点・兵科・配置・防衛戦術を事前に公開用スナップショットとして登録する。
- 対戦は**非同期**かつ**完全自動**。オンライン同席や試合中操作は不要。
- 勝敗によりレーティングが変動する。
- 公式戦のみサーバーが権威的に計算する。開発・PvE・NPC戦・自分の戦術のテストはブラウザで無制限実行する。
- 公式戦の負荷・濫用・レート操作を抑制するため、ランク戦チケット制を採用する方向。
- 実装時には相手の非公開戦術をクライアントへ配布しない。

**この文書に記した公式戦は未実装です。** ローカルフェーズではAPIやアカウント管理を作りません。

## 2. 権威境界

    Browser: Edit / Local Compile / Local PvE / Debug / Test
                 |
                 | Signed-in official match request (future)
                 v
    Admission API: authenticate, authorize, validate ticket & snapshot
                 |
                 v
    Match Authority: fix both immutable strategies + ruleset version
                 |
                 v
    Authoritative Simulation: revalidate and run shared battle semantics
                 |
                 v
    Atomic Settlement: persist result, ticket accounting, ratings
                 |
                 v
    Publicly permitted result / redacted replay / rankings

ブラウザが申告した「勝敗」「CU」「正当な編成」を公式戦の根拠にしません。サーバーで戦術IR・軍備・コスト・ルールを再検証し、公式シミュレーションを実行します。

## 3. 対戦レコード（契約の方向性）

- Match IDと冪等性キー。
- エンジン／ルール／DSL／IR／CUスキーマの各バージョン。
- 攻撃側と防衛側の不変戦術・軍備スナップショットのハッシュおよび実体へのアクセス。
- 戦場と初期状態、結果、終局Tick、戦術実行の検証証跡。
- レート変更の元・先の値、処理結果、署名またはサーバー保証の来歴。

結果ハッシュやソースハッシュだけではリプレイ再実行に不十分です。必要なスナップショットにアクセスできる保存設計と、閲覧側への情報公開制御が必要です。

## 4. ランキングの公正性

任意相手への連勝や同一防衛スナップショットへの再攻撃だけで、無限にレートを稼げない制度が必要です。

- レート公式戦の回数はチケット・利用上限で制御する。
- 同一相手／同一防衛版からの反復取得に制約を課す。
- プレイヤー自身や協力アカウントによるレート移転を考慮する。
- レート変動とチケット消費は原子的／冪等に確定する。
- 無料の公開AIへの模擬戦は、公開・配布を明示的に許可した相手に限る。
- 戦術プログラムの非公開設定と公開リプレイの機密性は別々に設計する。

攻撃レート・防衛レートを分ける案、Elo等の具体方式、チケット枚数・回復周期は**未決定**です。レートに影響するチケットの有料販売は競争公平性との衝突があるため推奨しません。

## 5. Cloudflareの位置づけ（推奨・未確定）

| コンポーネント | 将来の候補 |
| --- | --- |
| Web配信 | Workers Static Assets等の静的ホスティング |
| 対戦受付・認証・結果照会 | Cloudflare Workers |
| チケットと対戦状態の直列化 | Durable Objectsまたは同等の強整合境界 |
| 戦績・ユーザー・ランキング | D1等の永続DB |
| 大きなリプレイ・共有戦術 | R2等のオブジェクトストレージ |
| 公式戦演算 | Workersで性能・制限を測定し、必要に応じて独立実行基盤 |

ゲームコアはCloudflare SDKやD1のスキーマに依存しません。Cloudflareは配信・認証・保存・権威処理のアダプターです。WorkersでWASM実行が適切かは、実戦負荷とCPU・メモリ制限を測ってから決定します。

## 6. OSSとユーザー戦術

コード・戦闘ルール・戦術言語・CUコスト表・エディタ・NPCキャンペーンは公開可能とします。ただし、個々のプレイヤーが非公開で登録した防衛戦術やアカウント情報は公開物ではありません。コードのOSSライセンスとゲームの商標・アセット使用許諾は別に管理します。

## 7. 将来の収益化

現時点で課金・広告モデルは未決定。競技的公平性を毀損する戦力・計算資源・公式ランク試行回数の有料優位は避ける方向とし、装飾等を候補に留めます。ローカル第一段階には課金コードを導入しません。
