# Senkei — 3Dグラフィック・アートディレクション

## 1. 位置づけ

本書はSenkeiの**戦闘描画とグラフィック制作**の設計正本。ゲームルール・戦術言語・勝敗計算の正本ではない。**実Battlefieldの地理・造形・カメラ・視覚受入**は [BATTLEFIELD-VISUAL.md](BATTLEFIELD-VISUAL.md) を専用正本とする。名称と責務は [COMPONENTS.md](COMPONENTS.md)、シミュレーションは [ENBU.md](ENBU.md)、表示データは [REPLAY.md](REPLAY.md)、画面体験は [UI-DESIGN.md](UI-DESIGN.md)、実装順序は [GRAPHICS-DELIVERY.md](GRAPHICS-DELIVERY.md)。

**合意済みの方向**: 立体的な3D戦場を2.5D的な俯瞰で見せる。Pixel 3Dを第一候補にし、手動の3Dアセット制作を必須とせず、Codexがコードで制作・調整・再生成できるようにする。レンダラーはEnbuから独立し、クライアント側で動作する。デスクトップ／モバイルの操作体験は別設計。

**デザインとしての基準案**: 下記の色・カメラ・エフェクト・品質段階。実際のレンダリングを評価して調整可能であり、未制作の見た目を完成品とは呼ばない。

## 2. ビジュアルコンセプト

**Pixel 3D Tactical Diorama — 立体ジオラマで「戦型の演武」を観察する。**

- 低ポリの立体地形、段差、進軍路、兵士、塔、双方の拠点を3Dで構築し、正投影寄りの斜め俯瞰で表示する。
- 地形・建物・ユニットの形、材質、影、光の方向、限定色パレットで一貫した世界観を作る。単なる3本の線や粗いピクセル化だけを完成形としない。
- 戦場シーンだけを低解像度RenderTarget等でPixel 3D化する。コード・文字・タイムライン・操作UIはネイティブ解像度で鮮明に表示する。
- Pixel 3Dを切り替えられるよう、メッシュの形状制作とピクセル描画パスを分離する。
- プレイヤーが観察する「戦線の押し引き」「進軍方向」「損耗」「塔の破壊」をグラフィックの第一優先とする。複雑な装飾はそれらを隠してはならない。
- カメラズーム時に個別の武器・装備・攻撃動作を視認でき、引いた画角では兵科のシルエットと集団の方向を認識できる。

## 3. 戦場の情報階層

| 情報 | 3D側の表現 |
| --- | --- |
| TOP / MID / BOT | 形と高低差を持つ3本の経路、地形の区切り、拠点の位置関係 |
| 陣営 | 味方・敵で異なる配色に加え、旗・輪郭・盾形状等で識別 |
| 兵科 | 頭部・装備・武器・輪郭・移動姿勢を共有パーツから作り分ける |
| 塔・本拠地 | 高さ・シルエット・損傷段階の差分 |
| 動作 | 出撃、移動、攻撃、被弾、撤退、施設破壊をリプレイイベントから演出 |
| 選択・注目 | ワールド空間上の輪郭・選択標識。高解像度の説明欄と連動 |
| 分析 | 許可された情報のみを、射程・経路・損耗位置などのオーバーレイで表す |

初期の表示用兵科候補は歩兵、重装兵、射手、騎兵、攻城兵。これは**Fixtureの見た目の例示**であり、Senritsuの正式な兵科Catalogや数値の確定ではない。レンダラーは未知のarchetypeにも安全なフォールバック表現を持つ。

## 4. 推奨スタックとレンダリング

| 責務 | 第一候補 |
| --- | --- |
| 3D Scene | Three.js + React Three Fiber |
| ブラウザGPU基盤 | WebGL2。WebGPU必須にはしない |
| 地形・施設 | プロシージャルGeometry、必要に応じGLBへ交換 |
| キャラクター | 基本形状の合成・共有パーツと派生モデル |
| 多数のユニット | InstancedMesh等、必要に応じLOD |
| ライト | 方向光＋環境光、安定した影、近接部の陰影 |
| Pixel 3D | 低解像度RenderTarget＋nearest-neighbor拡大、パレット／エッジ制御 |
| 描画結果の確認 | Playwrightと実画面目視 |
| 将来の高品質化 | GLB、アニメーション、WebGPUを実測後に評価 |

シェーダーによるPixel化がHUDを劣化させないこと。拡大縮小やカメラ移動時のちらつき、ピクセル密度の変動、影のジャギーを実画面で評価し、必要ならカメラ補正・内部解像度の量子化を施す。

## 5. 視覚トークンの基準案

- **環境**: 群青・スレート寄りの落ち着いた戦場外装、自然な草・土・岩の低彩度。
- **味方**: 青／シアン系＋固有シルエットと旗。
- **敵**: 朱・赤土系＋固有シルエットと旗。
- **重要イベント**: 琥珀系、対象位置と時刻を同期。
- **文字**: UIは読みやすい日英フォント。Tick・CU・兵数は等幅数字。コード表示と戦場UIのタイポグラフィは分離。
- **エフェクト**: 確定イベントを補助する短い視覚反応。ビジュアルだけでゲーム上のヒットやダメージを算出しない。

カラーコード、ピクセル密度、影の濃さ、モデルの解像度はデザインパラメータ。ゲームルールに埋め込まない。色覚差・小画面・明暗差のため、色のみで兵科・陣営・勝敗を区別させない。

## 6. AI/Codexに適した再現可能なアセット制作

1. 地形・兵士・塔の造形パラメータ、生成元スクリプト、材質、カメラと光源をソース管理する。
2. 最初はThree.js等のGeometryで生成し、造形が必要なときだけBlender Pythonによる生成を選べるようにする。
3. 外部素材を利用する場合は、assetKey、出典、ライセンス、加工条件をmanifestへ記録する。許諾不明の素材を混在させない。
4. GLBを追加する場合はglTF Validatorによる形式検証と必要に応じたglTF Transformによる最適化を行う。
5. 生成元と生成成果物を分離し、アセットの生成・検証・バージョン追跡を再実行可能にする。
6. 元の戦闘イベントとは独立のappearanceKeyとモデルmanifestで見た目を解決する。GLBファイル名・アニメーション名をEnbuのロジックに埋め込まない。
7. 固定Fixture＋カメラ＋画面解像度を記録し、視覚回帰を検出できるようにする。

## 7. Rendererの境界と品質方針

    Enbu (将来は公式戦サーバー) → PresentationReplay
                                      ↓
                              Replay Decoder / Player
                                      ↓
                             read-only Display State
                                      ↓
                   Scene Adapter / Units / Structures / Effects
                                      ↓
                           Pixel 3D Render Pass
                                      ＋
                           High-resolution UI

- Enbuの戦闘計算・Senritsuの効果判定・Jinreiの戦術実行をRendererへ移さない。
- 位置・攻撃・被害・消失などはReplayの確定情報を投影して表示し、描画FPSや速度変更によって結果を変更しない。
- 戦術ソース、IR、敵の非公開状態、内部CUトレースをPresentationReplayから推定して補完しない。所有者の診断は別の認可境界を用いる。
- クライアント側の負荷は許容するが、描画できない環境では明示的な失敗と復帰導線を表示する。将来的にHigh / Balanced / Lowを提供可能な設計にする。

## 8. 画質の受入視点

- 標準カメラで3レーン・双方の拠点・戦線方向がわかる。
- 標準倍率で少なくとも3兵科、ズーム時は5兵科候補をシルエットで区別できる。
- 100体相当の密集Fixtureで兵数・戦線・攻防方向を読み取れる。
- 攻撃／被弾／破壊は静止画でも動画でも場所と意味を理解できる。
- Pixel処理でUIの文字が劣化せず、ズーム時の画素ちらつきが許容範囲である。
- 視認性・演出の魅力は実ブラウザのスクリーンショットと操作を見て評価する。ビルド成功だけでは満たさない。

## 9. 次期MOBA型マップとの境界

戦場の具体的なノード・エッジ、固定橋、河上MID基地、三トラックと交戦領域は [BATTLEFIELD.md](BATTLEFIELD.md) が正本。Rendererは通行・射程・隊列・建設状態を推定または再計算しない。

現行のGraphics G1はコンパクトな三レーンの固定Fixtureであり、最新のゲームマップそのものではない。[WORLD.md](WORLD.md) で合意した次期Senritsuの戦場は、対角側に本拠地を置く**広いMOBA型のTOP/MID/BOT三レーン**と、レーン間の**複数の中立モンスター地点**を持つ。新規Fixture／Enbu Adapterでこれを表示できるようにするが、Rendererから通行権、敵位置、XP、移動倍率を計算し直さない。

Pixel 3DとSmooth 3Dの選択は描画品質の問題であり、会話ではSmooth 3Dも許容可能との評価がある。比較は表示用オプション・アートディレクションの範囲に留め、ゲーム規則の変更を伴わない。既存のPixel 3D実装をドキュメント修正だけで置き換えたことにはしない。

## 10. G2 Hero Atelierと画風の統一

[HERO-ATELIER.md](HERO-ATELIER.md) をHero画面と戦場で共有するStylized 3Dアートディレクションの正本とする。G1のPixel 3Dは任意の描画パスとして保持し、Smooth 3Dを同等に評価する。Hero Detail用モデルと戦場LODは同じHero identity／装備／材質系列から生成する。写実寄りモックとG1ローポリを無条件に混在させない。
