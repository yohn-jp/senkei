# 数理的圧縮の導出・境界・反例

> 本文の数値は説明用。RulePlan、離散化、状態の意味を推測で変更しない。閉形式の適用は各RulePrimitiveの演算契約で証明する。

## 1. 基本式と計算量

完全な意味状態を `X_t`、時間依存を含む遷移を `F_t` とする。

```text
X[t+1] = F_t(X[t])
X[t+k] = (F_{t+k-1} ∘ ... ∘ F_t)(X[t])
```

`F_t`を逐次`k`回呼ぶ代わりに等価な`G_{t,k}`を求める。物理計算量が`o(k)`になるかはモデル依存。明示的な全Tick/全ユニットの出力が必要なら、**少なくとも出力サイズ分**の処理/書込みが残る。

## 2. 一次・アフィン型

`x[t+1]=x[t]+v`（区間中vが不変で、同じ演算環境なら）`x[t+k]=x[t]+kv`。

連立アフィン型`X[t+1]=AX[t]+b`について同次座標を導入する。

```text
Y = [X;1],  M = [[A,b],[0,1]],   Y[t+k] = M^k Y[t]
```

一般の密行列なら二乗法によって`O(d^3 log k)`演算（通常の密行列乗算の単純実装）で、疎/三角/対角構造なら削減可能。実際の勝敗は`d`とk、数値semanticsによる。巨大な行列に変換すること自体は最適化ではない。

**三角例:** `c[t+1]=c[t]`、`b[t+1]=b[t]+c[t]`、`a[t+1]=a[t]+b[t]` は、飽和のない整数環なら

```text
c[t+k] = c[t]
b[t+k] = b[t] + k*c[t]
a[t+k] = a[t] + k*b[t] + k*(k-1)/2*c[t]
```

となる。これが状態変数を個体単位ではなく**連立依存単位**にする理由。

## 3. 射程・視界への進入

位置`p_A(t)=p_A0+v_A*t`、`p_B(t)=p_B0+v_B*t`とし相対`r(t)=r0+vr*t`、射程Rなら、ユークリッド距離を仮定した**説明用**連続式は

```text
(vr·vr)t² + 2(r0·vr)t + (r0·r0 - R²) <= 0
```

これを二次不等式として解き、候補の最初の整数Tickを求める。ただしSenkeiの実際の判定はWorldのトポロジー/エッジ/ノード/固定座標/射程/視界規則を使う。二次式を適用できると決め付けず、距離関数`D(World,pA,pB)`が区間内で変わらないこと、丸めた位置での厳密検査、フェーズを要求する。相対速度0、初期から射程内、出入り複数回、接線接触、非単調な経路変更、同Tick複数対象のtie-breakを別ケースにする。

## 4. ガードが変わる時刻の導出

`H(t,X[t])`をJinreiやSenritsuのガードとする。次の境界`τ=min{k>=1 | H(t+k,X[t+k]) != H(t,X[t])}`を証明できれば区分的な式に分割する。ただし`H`がTruth三値であるとき **true→unknown**、**unknown→false** なども別の境界。

HPが`HP0-kD`で単調減少し、撤退条件が`HP < h`なら、最初の整数kは、D>0として厳密に`k > (HP0-h)/D`を満たす最小非負整数。攻撃は離散時刻にしか発生しないので、実際には打撃回数と攻撃可能Tickを合成して判定する。

**ガードの真偽が不変**でも、`ordered`の評価パス、集合サイズ、残CU、出力イベントが不変とは限らない。スキップ証明はすべてを含む。

## 5. 固定攻撃の集約と死亡時刻

初回命中Tick`t0`、間隔`I>0`、一撃D、同値区間中の命中回数を`K(t)`とすると、Shield/回復/防御/上限/無敵/移動/行動ロック等が一切介入せず、すべての打撃が同じ効果を持つ**限定例**に限り`HP(t)=HP0-D*K(t)`。死亡の最初のヒット番号は`ceil(HP0/D)`。ただし終局・XP/成長/対象消失/連携変化が発生するTickが新たな境界である。同時双方攻撃は**同一Snapshotから収集して同時コミット**し、一方を先に死亡判定して他方の攻撃を消してはならない。

## 6. 周期・有限状態

周期IのTimerは`t=t0+nI`で候補時刻を直接列挙できる。複数周期の繰返しは合同式、最小公倍数、場合によりChinese Remainder Theoremを検討。ただし周期の合成期間`lcm(I1,I2,...)`が膨大になり得るため、常に事前展開しない。

有限状態システムで完全状態+Tick位相が`X_i=X_j`なら、`j-i`周期のfast-forward候補。ただし累積CU、統計、Replay、行動履歴や絶対Tick依存の比較を失わないか証明する。状態の見かけの一致は不十分。

## 7. 離散演算の危険な変形（反例）

反例1: `x[t+1]=floor(x[t]+1/2)`, `x[0]=0`。毎回丸めれば永遠に0。一括`floor(0+k/2)`はk=2で1。**繰返し丸めとまとめ丸めは一般に非同値**。

反例2: `x[t+1]=min(M,x[t]+v)`を符号自由のvに対し`min(M,x[t]+kv)`と置換できるとは限らない。上限に張り付いた後にvや補正が変わる場合、過去の飽和が将来へ影響する。

反例3: `(a+b)+c`と`a+(b+c)`は、オーバーフロー・飽和・逐次整数除算を含むと一致しないことがある。数学的環と実装の演算意味論を区別する。

反例4: ユニットAを100Tick先に進めてからBを進めると、両者が途中で射程に入るTickと同時攻撃を見落とす。**unit-majorそのものは時間圧縮ではない**。他者への因果境界で同期する。

反例5: 敵が不可視の間に将来位置を内部的に計算できても、Jinrei観測`Known`へ昇格させるとFog/権限違反となる。

## 8. 非線形と非単調の扱い

- **関数が既知**であることと、**短い閉形式で表せる**ことは異なる。決定論でも単純な`F^k`が存在しない可能性がある。
- 単調か不明な条件はInterval/Abstract Interpretationによる安全な区間証明を優先する。証明できない区間は逐次評価または安全な小区間へ分割。
- 同時に複数Guardが成立する場合は最小Tickを求め、そのTickに関係する**全ガード**を同じSnapshotで評価してSenritsuの全順序で解決する。
- 式サイズが反復合成で指数的に増えることがある。DAG化・Budget化・切り詰めてFallbackを可能にする。

## 9. 区間ジャンプの証明項目

`jump(t,k)`は次を証明できる場合のみ採用:
1. 計算された`X[t+k]`が逐次`k`回の結果と同一。
2. 区間中の全TickのJinrei観測/Truth/Intent、RulePlan各フェーズの意味と競合が一致。
3. Costed Logical IRの評価分岐と論理CU、超過時停止が一致。
4. 要求される各Tickのイベント/診断/Replay投影が同一の順序・権限で復元可能。
5. 最初の勝敗/ホスト上限・イベント容量超過/タイムアウト境界を飛ばさない。
6. 型・数値範囲・整数/固定小数点・丸め・飽和の演算結果が一致。

証明が難しいときは **Safe Fallback（元のTick実行）** を選択し、正しさとベンチ性能を切り離す。
