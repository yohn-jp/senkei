# RUN-20261029-002: Senrei expanded scheduling benchmark

Status: MEASURED SYNTHETIC MODEL / NOT PRODUCTION ENBU. The benchmark is an independent Node.js simulation with shared-target HP, simultaneous per-Tick attack commitment, constant-speed approach, independent periodic visibility gates, spawn delays, and target-death cancellation. It does NOT implement Jinrei three-valued Known/Unknown semantics, CU, Fog of War, bridge reservations, or full Replay.

## Method and correctness

Seven methods: per-Tick global sweep, Active Set, binary-heap event scheduling, Tick bucket scheduling, exact periodic residue-cycle aggregation plus monotone death-time search, target-local hybrid (first-volley kill / event / recurrence), and two-level adaptive selector (global plus target-local). For 14 scenarios × five actor counts × eight horizons = 560 fixtures, plus 200 deterministic randomized fixtures, six candidate methods matched the Tick oracle on final positions, target HP, next attack Tick, attack count, attack Tick sum, and all attack-Tick sequences: 4,560 differential comparisons PASS.

Measurements: Linux x64, Node v22.16.0, AMD EPYC 9V74. Report values below are median milliseconds per execution. Copies, state comparisons and JSON serialization are excluded; event materialization is included only in timeline mode. Tiny runtime measurements have JIT, GC and CPU noise. Different tables are separate benchmark runs.

## Analysis

- In 512-actor Result-only measurements the fastest method changes: periodic six scenarios, Active four, Heap two, and hybrid two. No single strategy dominates.
- Dense event queues can be slower than a simple Tick sweep: dense_hits Heap 337.687ms vs Tick 22.573ms, while periodic recurrence is 0.115ms. Event-count reduction matters more than queue design.
- Early death favors simple execution. shared_small Active 0.012ms vs periodic 0.526ms at 512 actors. First-volley lethality detection avoids unnecessary death-time binary search.
- A periodic visibility guard permits a finite-state recurrence of firing phase modulo visibility period. Repeated cycles are aggregated analytically; monotone cumulative damage identifies the first lethal Tick by binary search. This model has no healing/shield/variable target selection.
- Results-only calculations are not equivalent to event materialization costs: for dense_hits, 427,000 attack Tick records must be generated. Periodic 0.023ms (result only) versus 22.700ms (full attack timeline) across separate benchmark runs; these measurements should not be used for precise cross-run ratios.
- The adaptive heuristic is not yet optimal; grouping, scanning and misclassification overhead can outweigh the selected solver. Distinguish cost of plan construction, horizon length, first attack, group size, predicted number of attacks, and output volume.
