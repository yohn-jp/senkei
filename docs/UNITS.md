# UNITS — Hero / Squad / Minion / Monster モデル

## 1. 位置づけ

この文書はSenkeiの**戦闘主体、5体のHero選択、Squad編成・連携、死亡と復活、Hero属性**を定義する次期Senritsu向けゲームデザイン仕様である。既存のsenkei.initialにHero CatalogやSquad機能が実装されていると主張するものではない。ゲーム上の事実はSenritsu、状態遷移はEnbu、判断はJinrei、視覚的表現はRendererがそれぞれ所有する。[WORLD.md](WORLD.md)／[COMBAT.md](COMBAT.md)／[BALANCE.md](BALANCE.md) を併読する。

**合意**と記した内容は会話で固定したもの。**候補／未確定**は詳細設計または数値調整の対象。前回の提案のうち後から変更されたものは、この文書に記した最新の内容を優先する。

## 2. Entity / Unit / Squad / Army の区別（設計原則）

| 概念 | 説明 | 戦術上の位置づけ |
| --- | --- | --- |
| Entity | 戦場に存在する型付きの対象 | Unit、塔、本拠地、その他の施設を包括 |
| Unit | 移動・攻撃等の能力を持つ個体 | Hero、Minion、中立モンスターが役割として該当 |
| Hero | プレイヤーが戦型に選択する高機能Unit | 個別の能力、経験値、レベル、スキル、Squad所属 |
| Minion | 自動進軍し戦線を維持するUnit | 視界とレーンの戦況情報の基礎供給源 |
| Neutral Monster | 第三者の中立Unit | ジャングルのリスクと報酬 |
| Structure | 塔・本拠地等のEntity | 守備・攻撃・勝利目標。Unitとは区別 |
| Squad | 同一陣営のHeroからなる**指揮と隊列の単位** | Solo〜Quintet、合流・分離、集団移動、連携 |
| Army / Senkei | 自軍のHero選択とSquad構成、戦略・事前スキル選択等 | プレイヤーが作る戦型の全体 |
| Formation | Squad内の位置関係と前衛・後衛の並び | 連携の成立と個別の攻撃・被弾 |

Squad自体を第6のHeroやダメージ対象として数えない。SquadはHero間の所属関係と動作の制約を表す。Squadの存在を前提としないMinionとMonsterは、HeroのようにSquadへ自動配属しない。

Entityは共通の型付きComponent（位置、HP、所有陣営、射程、移動能力、成長など必要なもの）を持つが、すべてのEntityへ同じフィールドを強制しない。ECSライブラリの採用は必須ではなく、SenritsuのDomain SchemaでデータとCapabilityの合法性を検証する。

## 3. Heroは5体固定（合意）

- 一つのSenkeiは**ちょうど5体のHero**を編成し、試合開始時には必ずその5体の所属Squadを定める。
- HeroはSenritsuのHero Catalogから選ぶ。**初期Catalogは12種類、前衛6／後衛6**。
- 前衛／後衛は**配置適性**であり、必ずその行に配置しなければならない命令ではない。Jinreiによる戦術とSenritsuの移動・戦闘ルールの許す範囲で行動できる。
- Heroを1〜4体だけ選ぶ「枠が空いた状態」や、Hero編成コストを使って選択数を変える方式は採用しない。Solo優位は5体を分散運用した際の戦況と経験値に現れる。
- Catalogは型付きデータ・能力から拡張する。**初期12種類を超えて増やす前提**であり、Heroの名前ごとにJinreiの予約語を増やさない。

同一種類のHeroを一つの戦型内に複数採用できるか、禁止するかは未確定。12種類から異なる5種類を選ぶ場合の組合せが792通りという事実を、重複禁止の合意と取り違えない。

## 4. Heroの三軸属性（合意）

初期Catalogを次の3軸で分類する。

| 軸 | 初期の値 | 意味 |
| --- | --- | --- |
| 配置適性 | 前衛 / 後衛 | 配置・隊列上で得意な位置 |
| 戦闘特性 | 防御 / 火力 / 支援 | 戦闘への主な貢献 |
| 戦術特性 | 強襲 / 制圧 / 遊撃 / 偵察 / 継戦 / 指揮 | 情報・機動・行動制限・継続運用などの役割 |

「前衛 × 防御 × 指揮」のような3属性の組合せをHeroの設計単位にする。属性は単なるラベルだけでなく、実際に公開するCapability・行動・シナジーの条件と結びつける。**属性名だけで一律の固定攻撃倍率を自動付与するという合意はない。**

初期は各Heroに主要な戦闘特性・戦術特性を定める。将来の追加Traitや複合Traitも型付きタグとして拡張可能とし、効果とコストはSenritsuで明示する。戦型のHero名や外見の変更はゲーム言語そのものの変更とは切り離す。

## 5. Squadの人数・初期分割（合意）

5体のHeroを1〜5のSquadへ**自由に分割**して初期編成できる。正の整数5の分割パターンは次の7通り。

| 初期の人数構成 | Squad数 | 戦術上の性格 |
| --- | ---: | --- |
| 1+1+1+1+1 | 5 | 完全分散、各地の独立判断 |
| 2+1+1+1 | 4 | 小規模連携と分散の両立 |
| 2+2+1 | 3 | 二正面＋独立行動 |
| 3+1+1 | 3 | 主力と二方向の偵察 |
| 3+2 | 2 | 二つの部隊による戦線運用 |
| 4+1 | 2 | 集中主力＋Solo |
| 5 | 1 | Quintetで全員集結 |

UI上の人数呼称は **Solo / Duo / Trio / Quartet / Quintet** を使う。これらはゲーム固有の分類表示であって、Jinrei言語コアの固定キーワードではない。

同一Heroは一時点で高々1つのSquadに所属する。存命の5 Heroは常に所属関係を持つ（Soloも人数1のSquad）。Squadは同一陣営のHeroのみからなり、複数Squadを同時に指揮できる。

## 6. 戦闘中の合流・分離（最新合意）

**事前にすべての再編成結果を固定する必要はない。** プレイヤーはJinreiで「どんな状況で合流・分離し、どこで再集合するか」を記述し、戦闘中の判断を自動化する。

- 合流・分離はプレイヤーが戦闘画面で手動操作するのではなく、**Jinreiが発行した型付きIntent**をSenritsuが解釈しEnbuが解決する。
- Squad同士の合流は**同一位置（ルールで定義する合流可能な距離）**に到達した場合だけ可能。例：Solo+Solo→Duo、Duo+Trio→Quintet。合計5体を超える合流は認めない。
- 分離もJinreiの命令とSenritsuの条件に従う。**勝手に自動分離しない**（死亡だけが自動離脱する例外）。
- 合流には移動と連携成熟の準備が必要。分離すればその編成についての連携効果を失う／再評価する。
- Jinrei側は複数Squadの現位置、所属、残人数、再集合条件を観測し、適切なCapabilityでIntentを生成する。Jinrei v0.1のstate/action/when/do文法を変えずSenritsuのドメインシンボルを追加する。

以前の「戦闘中のSquad分離不可」という案は**後の合意によって撤回済み**。同一Squadとして一緒に進軍しているあいだは隊列を維持し、Jinreiによる合法な分離の後は別のSquadとして行動する。

合流判定の数値距離・座標境界、合流と分離の所要Tick／クールダウン／CU、同時に複数の合流Intentがある場合の競合優先順位、Squad IDの存続・解散・再採番方法は未確定。競合をソース順・HashMap順・実行環境の都合で決めず、Senritsuで全順序を定義する。

## 7. Squadの機動力と連携（合意）

Squadに所属して行動しているHeroの移動には、その時点の**Squad所属人数**による倍率を適用する。

| 人数 | 呼称 | 速度倍率 |
| --- | --- | ---: |
| 1 | Solo | ×1.00 |
| 2 | Duo | ×0.95 |
| 3 | Trio | ×0.90 |
| 4 | Quartet | ×0.85 |
| 5 | Quintet | ×0.80 |

[WORLD.md](WORLD.md) の地形×Minion視界倍率と乗算する。Hero個々の基本速度からSquad全体の実際の移動速度を導く具体規則（最も遅いHeroに合わせる等）は未確定。速度倍率は**計算資源CUとは別**。

人数が増えるほどSquad連携による戦闘性能は**非線形に高くなる方向**だが、連携の確保には時間を要する。隊列維持や相互位置を条件とし、Squadを作成・合流した瞬間に最大ボーナスを与えない。

連携の実際の効果は単純な攻防倍率だけに限定しない。護衛・集中攻撃・回復・妨害・視界・指揮など、Heroの能力と行動のシナジーとして表現できる。特定Hero名の固定セット効果を主役にするのではなく、属性・能力・位置・タイミングで有効になることを目指す。

**Soloの強み**は追加の魔法的な火力補正ではなく、人数倍率上の機動力、即応性、複数地点での観測・目標遂行、経験値の分散を避けること。Quintetが常に最適解にならないバランスを [BALANCE.md](BALANCE.md) で検証する。

## 8. 死亡、自動離脱、復活と再合流（合意）

1. Heroが死亡すると**直ちに所属Squadから自動離脱**する。死亡中のHeroは生存Squadの人数・移動倍率・連携人数に含めない。
2. 残存Heroは**人数が一段階下がったSquadとして活動を継続**する。例：Quintet→Quartet、Duo→Solo。0体になったSquadは解消する。
3. 死亡HeroはSenritsuが規定する**クールタイム経過後に自軍拠点で復活**する。
4. 復活したHeroは**必ずSolo**となり、以前のSquadに自動復帰しない。
5. 元のSquadでも別のSquadでも、Heroが同じ位置へ移動して**Jinreiの合流Intent**を出し、Senritsuの条件を満たせば再合流できる。
6. 死亡・復活・合流の移動と連携状態はEnbuが決定論的に更新する。

死亡後の経験値・レベル・取得済みスキルを保持するか、復活時HP／MP等をどう扱うか、クールタイムの長さとレベル依存、死者のXP獲得資格、連携成熟度の下降・再合流時の引継ぎは未確定。**提案**としては復活時にレベル・取得スキルを維持し、合流時は新しい連携を成熟させ直す方針だが、これは実測を経て確定する。

## 9. 成長とスキルツリー（合意）

- Heroは戦闘中に経験値を得てレベルアップし、**基礎ステータスが成長し、複数のスキルを取得できる**。
- Heroごとのスキルツリー・成長経路は**戦型の編成時に選んでおく**。プレイヤーが戦闘中に手動で選択しない。
- レベル条件に従う取得・強化はSenritsuが自動で解決でき、取得済みスキルの使用条件・対象・タイミングはJinreiから型付きCapabilityで制御できる。
- Heroごとのスキルツリーを固定した巨大なコード分岐としてEnbu／Jinreiへ埋め込まず、Senritsuのバージョン付きHero Catalogに定義する。
- 回復、索敵、攻撃、指揮、連携強化などのスキル効果は、有限の遷移プリミティブとCapabilityで表現する。

具体的なレベル上限、XPテーブル、成長率、各スキルの名称・解放レベル、ツリー分岐数、コスト、取得の先行条件、SkillPoint制の有無は未確定。

## 10. XP・視界・指揮の関係

経験値は獲得イベントで**対象資格のあるHeroに均等分配**する。Squadの名簿人数を無条件に分母とするのではなく、Senritsuで判定した対象資格の人数を使う。したがってSoloで討伐したHeroは、同じ報酬を5人で分ける場合よりも速く成長し得る。[COMBAT.md](COMBAT.md)、[BALANCE.md](BALANCE.md) が詳述する。

Minionの中核価値は視界。Minionが前進・生存している範囲の視界は陣営に共有され、Hero／Squadの移動速度に好影響を与える。Minion自体のレベルやSquad加入は合意していない。

Jinreiが観測できるのはSenritsuのObservation Schemaで許された情報。現在観測できない対象はUnknownであり、過去観測しただけで現在の位置がKnownになるわけではない。Hero死亡、Squad名簿、技能取得・クールダウン等の観測項目は、Jinrei文法ではなくSenritsu側に追加する。

## 11. 導入時に必要なコンフォーマンステスト

- 12種から必ず5Heroを設定し、7種類の人数分割と所属一意性を検証。
- Solo〜Quintetの人数倍率と、分割・合流・死亡後の更新を検証。
- 初期編成・途中分離・合流の命令、距離不成立、所属重複、合計6人以上、異陣営合流を拒否。
- 連携は一定時間維持しないと完成せず、死亡・合流・分離で規定の遷移となる。
- 死亡時に自動離脱し残ったSquadが行動を続け、クールタイム後に拠点でSolo復活する。
- 復活後に明示的なJinrei合流条件がない場合、元Squadへ自動で復帰しない。
- 進軍・視界・XPのSolo優位とSquad連携の優位を、同じSenritsu版の複数テストケースで比較する。
- Jinreiの不正な能力・観測・所属変更を型検査／RulePlanで拒否し、両陣営同時処理で結果が揺れない。

## 12. 未決定の具体値・規則

Hero重複選択の可否、5体の初期スポーン位置、基礎ステータスと成長量、スキルツリーの解放・分岐、XP対象判定の距離と死亡時の資格、Squadごとの隊列形状、低速メンバーと編隊速度の関係、連携成熟時間と非線形効果値、分離・合流の距離・時間・コスト・優先順位、死者の進行状況保持、復活クールタイム、合流IDの取り扱い、中立Unitの特殊な状態。

合意済みの5体固定・初期12種6対6・人数別速度倍率・死亡→Solo復活の規則を、調整用の未決定値と混同しない。
