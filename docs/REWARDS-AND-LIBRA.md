# REWARDS-AND-LIBRA — 装備報酬・マーケット・通貨の合意境界

## 1. 位置づけ

装備収集のモチベーションと、会話で合意した市場・通貨の方向を保存する。本書はオンライン経済の実装指示ではない。ガチャとHero関係性を検討対象とし、リソース生産、研究、内政、EOS／GS2の選定、中央コミット・検証方式は引き続き保留する。

装備性能は [EQUIPMENT.md](EQUIPMENT.md)、信頼・会話・連携は [HERO-RELATIONSHIPS.md](HERO-RELATIONSHIPS.md) を参照する。

## 2. 決定した原則

| 項目 | 合意内容 |
| --- | --- |
| 装備在庫 | 重複装備を無制限に保持できる。戦闘による破損はない |
| マーケット | 装備を通貨で売買する方向とする |
| 最低保証 | 公式マーケットメーカーによる最低買取額を設ける方向 |
| 通貨 | **Libra（リブラ）** |
| 発行者 | **新規Libraの発行は公式マーケットメーカーのみ** |
| 可視化 | 通貨の総発行数を閲覧できるようにする |
| 戦闘 | 戦闘参加・試行錯誤に消費資源を要求しない |

プレイヤー間売買は既存Libraの移転であり、新規発行ではない。勝利・ログイン・研究等を別の発行経路として追加しない。マーケットメーカーの買取を発行経路とする方向だが、価格表・発行量調整・実装方式はまだ決めていない。

## 3. ガチャの方向と未決事項

勝利や課題達成の後に装備を引く期待感を作る。装備を主な排出対象とし、重複品は所持や売却に価値を残す方向を検討している。

ただし「勝利ごとに必ず1回」「装備は例外なくすべてガチャ限定」「特定重複品が進化に必須」といった仕様は未確定。抽選権利、配布頻度、確率、保証、対象プール、無料／有料、進化との関係も未決定である。

ガチャだけオンラインにする案は有力候補として議論したが、抽選権利・報酬の検証や取得状態の正本を含むオンライン方式は、後回しにする判断を維持する。署名・再計算・戦力計算だけで装備取得の正当性まで証明できたと扱わない。

## 4. Libra統計の意味

公開する総発行数は、マーケットメーカーによって実際に新規発行された量を表す。売買高や資産評価額と混同しない。

現在残高や回収量も表示する場合は、累計発行量・累計消滅量・残存量を定義して照合する。保留・取引拘束中の残高、運営保有、回収後再使用する通貨をどこへ数えるかを明示し、移転を消滅として数えない。これらの詳細な集計範囲は未決定である。

通貨名から現金換金、暗号資産、ブロックチェーン、投資商品としての性質を追加しない。

## 5. 採用済みと混同しない案

次は過去に提示した選択肢であり、確定仕様ではない。

- ランク別最低価格の具体額、排出率、買い取り上限・価格変動方式。
- マーケットメーカーが買い取った装備を消滅させるか、保有・再販売するか。
- プレイヤー取引の手数料、徴収Libraを消滅させるか、別主体へ移転するか。
- 固定価格出品、注文板、オークション、取引拘束・キャンセルの詳細。
- Libraによるガチャ購入や進化支払い、研究・内政での用途。
- 全取得履歴の再検証方式、サービスプロバイダ。

装備・信頼・戦術のゲームデザインを進めるために、これらの経済・オンライン実装を先に完成させる依存関係は作らない。

## ローカルと公式の確定境界

ローカルPvEはオフラインで自由に実行できる。ローカル結果だけで公式装備、公式抽選権、Libraを発行しない。公式所有権、抽選確定、決済は将来の権威サービスだけが確定する。サービス不在はunavailable / not configuredであり、ローカル保存成功を公式取引成功と表示しない。

共通取引契約は安定したOperation / Request ID、権威identity、submitted / pending / committed / rejected / outcome_unknown状態、冪等commit、同一要求の照会、永続的な取引証拠を持つ。Result identityと取得・決済記録は別に保持し、local / officialの混同を拒否する。確率、プール、報酬条件、価格、手数料、回収処理は未決定であり、値なしの発行・抽選・購入経路を作らない。
