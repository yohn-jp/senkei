# WORLD — 初期Senritsuの戦場・視界・中立領域

## 1. 位置づけと確定度

この文書はSenkeiの**次期ゲームデザインとして合意した戦場構造**を整理する。ノード・エッジ・距離・橋・三トラック・ノード交戦の具体契約は [BATTLEFIELD.md](BATTLEFIELD.md) を正本とし、WorldデータとCompilerの責務は [WORLD-DEFINITION.md](WORLD-DEFINITION.md) を正本とする。戦場の具体的なRulePackageやマップデータを既に実装したという意味ではない。ゲームとルールの責務は [COMPONENTS.md](COMPONENTS.md)／[SENRITSU.md](SENRITSU.md)、戦闘は [COMBAT.md](COMBAT.md)、戦闘主体は [UNITS.md](UNITS.md)、係数・調整は [BALANCE.md](BALANCE.md) に従う。

用語：
- **合意**: 会話で採用した規則・設計方向。
- **設計原則**: 合意から必要となる境界・不変条件。
- **未確定**: 詳細アルゴリズムや具体的な数値。実装の際に暫定案を採用しても、合意済みの値と混同しない。

現行の senkei.initial と G1 の三本の短い平行路は、ローカルPvE／描画の**既存実装と検証Fixture**である。PR #3ではNext Worldの表示・実戦連携が実装されたが、[BATTLEFIELD.md](BATTLEFIELD.md) の橋・三トラック・ノード交戦を実装・検証済みという意味ではない。新しいSenritsu版と、Enbu・Rendererの契約更新が必要になる。

## 2. 戦場の地理（合意）

- 両陣営の本拠地を対角側に配置する**MOBA型の三レーンマップ**を基本とする。TOPとBOTは外周寄り、MIDは中央の接続路とする。
- 各レーンには進軍・対面・防衛の意味があり、塔・本拠地への攻撃が成立するだけの距離を持たせる。従来の短い戦闘盤ではなく、進軍・撤退・回り込み・先回りが見える**広い戦場**を設計する。
- レーン間は空白ではなく、森・地形・複数の**中立モンスター地点（ジャングルキャンプ）**と、レーン間移動のための経路を持つ。
- 三つのレーンは独立した戦線として進むが、Hero／Squadは戦闘規則と通行可能な経路に従い、レーン間・ジャングル間を移動できる。
- マップの表示は立体地形であってよいが、戦術の進路・距離・視界・交戦判定は**Senritsuの論理ワールド**が所有する。グラフィックスの地形やカメラを変更しても計算結果が変わらない。

概念的には「自軍本拠地 → TOP／MID／BOT の各戦線 → 敵本拠地」であり、隣接するジャングル経路が横方向の移動と中立目標の争奪を可能にする。初期トポロジーと仮距離は [BATTLEFIELD.md](BATTLEFIELD.md) に定義する。座標埋め込み、経路幅、効果の数値調整は版付きパラメータ。

## 3. 論理ワールドと地形（設計原則）

| 概念 | 保持する意味 |
| --- | --- |
| World / Map | マップ識別子、陣営別の拠点、進軍経路、通行可能領域、地形 |
| Region | レーン、ジャングル、拠点などのエリア分類 |
| Navigation | ノード・経路／接続グラフ、距離、通行権、障害物 |
| Position | 位置、必要に応じた方位・経路上の進捗 |
| Vision Source | 観測を発生させる所有者、場所、範囲、遮蔽条件 |
| Objective | 塔、本拠地、ジャングルキャンプ等の戦略目標 |
| Timed State | 出撃・再出現・復活のためのTickとクールタイム |

マップ設計はSenritsuの**版付きデータ**。静的Topology・Metric・Terrain semanticsと描画用Presentationを宣言的Worldとして分離し、検証・Compileする契約は [WORLD-DEFINITION.md](WORLD-DEFINITION.md) を参照する。Enbuは検証済みの地形・ナビゲーション・視界遷移を実行する。Jinreiは公開された観測とCapabilityだけで進路や攻撃目標を選択する。RendererはReplay上の位置・イベントを3Dへ投影するが、通行可否や最短経路をルールとして再計算しない。

地形の増設で新たな物理的処理が必要なら、Senritsuデータの追加だけで済むと決めつけずEnbuの有限な遷移プリミティブを明示的に拡張する。

## 4. 移動速度：地形とMinion視界（合意）

**レーン速度係数 ×1.00、ジャングル ×0.80。味方Minionの現在の視界内は追加で ×1.20。** これらは移動速度への倍率であり、Jinreiが消費する論理CUではない。

移動の基本式：

    actual_speed = base_speed × terrain_factor × minion_vision_factor × squad_size_factor

Squad人数係数は [UNITS.md](UNITS.md)、[BALANCE.md](BALANCE.md) で扱う。速度倍率は乗算であり、視界ボーナスの重複加算・乗算はしない。味方Minionが複数いて視界が重なっても **×1.20は一回だけ**。敵Minionや、Minion以外が観測する範囲を同じボーナスへ自動的に含めない。

| 地形 | 味方Minion視界なし | 味方Minion視界あり |
| --- | ---: | ---: |
| Lane | ×1.00 | ×1.20 |
| Jungle | ×0.80 | ×0.96 |

「移動速度を上げる」ことと「道が安全・通行可能である」ことは別。視界があっても敵の障害、交戦、通行禁止の制約はSenritsuに従う。Minionの視界が移動速度に反映される対象は**Hero／Hero Squad**を基準とし、Minionや中立モンスターへの適用は未確定。

個々の移動区間がLaneとJungleをまたぐ場合、区間の領域や時間変化に応じて適切な係数を適用する必要がある。Tick内の評価タイミング、境界上の分類、対象判定、加速の端数規則は未確定で、Enbuの確定フェーズとして後で仕様化する。独立した速度係数と移動**コスト**の逆変換を混同しない。

## 5. Minion：戦線と情報の供給者（合意）

MinionはMOBA型のレーンを自動進軍する基本ユニット。射程内の敵や施設へ基本戦闘規則に従って交戦し、継続的な戦線を作る。ただしSenkeiで特に重要な価値は**情報**にある。

- 生存中の味方Minionが前進すると、その観測可能範囲が前へ広がる。
- その視界は原則として**陣営全体へ共有**する。異なるレーンのHeroのJinreiも許可された観測を利用できる。
- Minionが視界を維持する間、範囲内を移動する自軍Hero／Squadは上記の移動速度優遇を受ける。
- Minionの死亡・後退は、戦闘戦力の損失だけでなく視界・安全な意思決定・機動経路の情報の損失を招く。
- Minion自体は戦場を停止させない基本挙動を持つ。出撃や基本進軍がJinreiの戦術を毎Tick要求する設計にはしない。

Minionへの個別指揮をどこまで許可するか、出撃周期、視界半径、攻撃値、波の構成、レーン外への侵入条件、XP／資源報酬は未確定。戦術からの変更可能範囲を決める場合も、Senritsuで型付きCapabilityとして公開し、Jinreiの文法を増やさない。

## 6. Fog of War と観測の意味（合意＋既存Jinrei契約）

- **Known**：今の観測スナップショットで対象や値を確認できる。
- **Unknown**：現在の観測では確定できない。ゼロ・不在・falseではない。
- **Last Known（履歴）**：過去に見た内容の記録。現時点のKnownに自動昇格しない。自動履歴保存の具体仕様は未確定。

Senritsuは視界、遮蔽、観測権限、公開可能な値を定義する。Enbuが同一Tickの陣営別スナップショットを確定し、Jinreiはその許可された情報だけを評価する。

[JINREI-GRAMMAR.md](JINREI-GRAMMAR.md) の観測値 Observed<T> とTruthの三値論理を維持する。比較対象がUnknownなら通常の大小・等価比較はunknownになり、別の is known / is unknown で既知性そのものを判定できる。未観測位置を「どこにもいない」と扱わない。Last Knownは履歴であって隠れた敵の現在位置を漏らすAPIではない。

**視界による速度補正**と**三値の判断**は別の規則。視界効果を受けたことから相手の非公開戦術や非公開座標を推定できるような公開APIを設けない。公式戦の公開Replayは [REPLAY.md](REPLAY.md) の許可リスト投影のみを用いる。

## 7. 中立モンスターとジャングル（合意）

- レーンの間に複数の中立モンスター地点を用意する。
- 中立モンスターは陣営のHeroから見ると攻撃可能な第三者。通常のHeroと同じ指揮権限は持たない。
- ジャングル攻略は、レーンを離れて戦力を投入する代わりに、Heroの経験値や資源等を得る戦略的選択肢になる。
- 中立キャンプの位置・状態を観測できるかは、MinionやHero等が与える視界とSenritsuのObservation規則に従う。
- 中立モンスターもSenritsuの規則に従いEnbuで自動行動する。プレイヤーがその場で操作しない。

キャンプの種類・数・配置、モンスターのHP／AI／索敵／追撃、討伐後の復活、報酬（経験値以外の具体的種類）、大型目標・強化効果の採否は未確定。これらをレベルシステムの意味論と混同しない。

## 8. 塔、本拠地、勝敗（合意と未確定の境界）

レーン上に防衛施設（塔）を、両軍の拠点に本拠地を配置する。**標準的な勝利は相手本拠地の破壊**であり、3レーン多数決ではない。塔の機能は進軍の障害・攻防の目標となること。詳細な射程・被弾・破壊順序・塔越しの本拠地攻撃可否等は別途Senritsuで固定する。

自軍拠点は死亡Heroの復活地点でもある。死亡・クールタイム・Solo復活は [UNITS.md](UNITS.md) の規則。両拠点同時破壊、時間切れ、最大Tick、塔の再生、特殊勝利条件は未確定。勝敗判定はEnbuがSenritsuのRulePlanに従って確定する。

## 9. 戦場の表示・デザインへの反映

G1のコンパクトなPixel 3Dサンプルは新マップの完成形ではない。地図が**対角配置のMOBA型で広く、複数ジャングルキャンプを持つ**ことは、新しいSenritsuのマップ／新Fixtureが完成した段階で [GRAPHICS.md](GRAPHICS.md) の表示へ適用する。Smooth 3DとPixel 3Dの比較は描画上の判断であり、Worldの戦闘規則には影響しない。

Rendererはレーン曲線・キャンプ・現在視界／Unknown・戦線の変化を、公開許可されたPresentationReplayから再現する。グラフィックの位置表示を使ってゲームロジックを再計算しない。

## 10. 検証すべきシナリオ（新ルール実装時）

1. 同一World／両戦型／Senritsuで結果・移動軌跡・観測・CUがネイティブとWASMで一致する。
2. Lane／Jungle、Minion視界の有無の4ケースで倍率の合成が一致する。
3. 同じ視界範囲にMinionが複数いても速度優遇が重複しない。
4. Minionが死亡・視界外になれば所定の時点で観測と移動補正が変わる。
5. 観測できない敵がKnown(不存在)にならず、JinreiでUnknownの伝播が正しい。
6. レーン・ジャングルを跨ぐ経路、混雑、通行不可、視界の境界で決定論的な結果になる。
7. 中立キャンプは未観測なら秘匿され、討伐・報酬・再出現がルールに従う。
8. 公開Replayに隠れた敵・戦術・内部観測を紛れ込ませない。

## 12. 地形・論理視界の効果（追加合意）

**視界半径＋地形の論理遮蔽**を基本モデルとする。地形は移動だけでなく、観測や戦闘にも型付き効果を持てる。ただし全地形に全効果を必須にはしない。

- **森林／ジャングル**：視界・発見条件と機動の違いを生む。単なる移動係数だけの地形にしない。
- **高台**：観測上の優位を与え得る。影響範囲・方向・有効半径は版付き地形効果で定義する。
- **岩場などの遮蔽物**：論理的な遮蔽領域を作ることができる。移動幅やCombat Domainとの関係はSenritsuで型付けする。
- **河川／橋**：渡河時間・被ダメに加え、必要なら局所観測を型付きで定義する。川の描画形状だけから通行や遮蔽を判断しない。
- **MID観測基地**：周辺の局所視界と、**許可された観測から得る敵の実際の移動方向**を提供する。全マップの全敵表示、未観測の目的地・Jinrei・未来予測は提供しない。

遮蔽形状は**World DefinitionのTerrain semantics**、半径・効果はSenritsuのルール値としてCompileする。Three.js Raycastや描画FPS・LODが観測判定を変更してはならない。敵の視認可否はEnbuの同一Tickの陣営別Snapshotが確定し、JinreiのKnown/Unknownへ投影する。

Minion視界によるHero移動速度×1.20（重複なし）、Lane×1.00/Jungle×0.80の合意を維持する。上記の**意味論は確定**、地形別半径・遮蔽マスク・高台補正・MID効果量等の**数値とマップ別データは版付きパラメータとして後から調整**する。

経路の合法性・経路選好の違い、見えていない敵を経路探索に利用しない制約は [BEHAVIOR.md](BEHAVIOR.md) を参照する。
