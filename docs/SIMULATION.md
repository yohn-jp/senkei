# 決定論的戦闘・再現性・診断

## 1. 確定した実行モデル

- 戦闘はプレイヤー操作を伴わず、自動で進行する。
- 初期の戦闘コアにダイス・命中乱数・確率イベントを入れない。
- 結果 = F(ルール版, 戦場初期状態, 両軍装備／配置, 両者の戦術IR, 戦術初期状態)。
- 上記の入力が同一なら、実行環境にかかわらず同じ結果・同じ論理トレースを再現できる。
- 同時刻処理、同順位のターゲット選択、端数処理、時間切れはルールが決定する。

## 2. Tick型の実行パイプライン（推奨）

1. 直前Tickまでの確定状態から、両陣営に同時に観測可能なスナップショットを生成する。
2. 各陣営の戦略／戦術VMを同一時点の状態に対して評価する。
3. 命令の合法性・予算・優先順位・競合を確定した順序で解決する。
4. 出撃・移動・攻撃・被害・回復・施設効果等を明示したフェーズで解決する。
5. 戦場状態を更新し、勝敗と終了条件を評価する。
6. イベント・命令・CU・状態ダイジェストを記録して次Tickへ進む。

重要なのは、「攻撃側を先に全部処理する」ことに由来する恣意的な優位を避けることです。解決フェーズの細目は、ゲームルールの詳細確定時に明文化します。両者の命令を同一スナップショットから評価することを原則とします。

## 3. 数値と順序

- 整数または仕様化した固定小数点の演算を優先する。
- 浮動小数点・SIMD・並列実行の差異によって結果が変わらないようにする。
- コレクション走査と競合解決の順序を規定し、ランダムなHashMap走査順に依存しない。
- ID、優先順位、同時攻撃／同時死亡、配列の境界、ゼロ除算、オーバーフローの扱いを規定する。
- 外部時刻、シード、OSの乱数、ネットワーク状態を試合の戦術判断へ混入させない。

## 4. リプレイと証跡

再現可能な最小入力は、エンジン版、ルール版、言語／CU版、軍備・戦場の初期スナップショット、コンパイル済み戦術IRと戦術メモリ初期値です。これを完全に保持して再計算すれば同じ結果になります。

デバッグ・高速シークのためのイベントログ、周期スナップショット、状態ダイジェストは派生データとして持てます。**結果やログのハッシュだけでは再実行はできない**ため、コンテンツアドレス付き保存時も元のスナップショットの保持方針が必要です。

- コアの戦闘結果と論理トレースには再現可能なシリアライズ形式を用いる。
- UI演出のフレームレートや補間はゲームロジックから切り離す。
- スキーマ版とルール版が合わない場合は黙って再生結果を変えず、非互換として処理する。
- 公式戦将来案では、所有者以外へのリプレイ公開範囲を考慮し、非公開戦術のソースや中間状態を漏らさない。

## 5. デバッグと改善ループ

- 任意Tickへの移動、状況観測、条件の真偽、発行された命令、無効な命令の理由を表示する。
- Tick別・レーン別・戦術別のCUを表示する。
- 変更前後のAIを同一条件・同一ルール版で比較できる。
- PvEで複数の異なる相手に対してベンチマークを実行する。
- 完全決定論のため、**同じ敵・同じ入力を100回走らせても勝率推定にはならない**。評価ケースを変える必要がある。
- 「MID塔破壊」「増援条件がFalse」など観測可能な事実と、「それが主因」など分析上の仮説は分離する。

## 6. 安全性とリソース

戦術VMは任意のホストAPIを呼べません。CU上限に加えて、メモリ、最大Tick、最大兵数、IR深度、入力サイズ、命令数、イベントログ容量などホスト保護上限を設定します。ローカル版でもブラウザの無応答・メモリ枯渇を避けます。

## 7. 必須の証明条件（実装時）

- 同一入力を反復実行し、結果・状態ダイジェスト・CUが一致する。
- ネイティブRustとWASMの同じゴールデンケースが一致する。
- テキストDSLとGUIが生成した等価IRで同じ結果となる。
- 攻守を入れ替えた対称ケースで、未定義の先手有利が発生しない。
- 競合同時命令・境界・時間切れ・CU上限超過を定義通りに処理する。
- 無効プログラム・不正なバージョン・過大入力を拒否する。
